# 去卡片化与直接作答（第五轮交互简化）

> 状态：**已实现**。用户诉求：`继续简化一下各个游戏，不需要有模式卡、构造块、规则卡之类的设置，游戏逻辑简单直接即可`。
> 覆盖：宿主外壳 + 6 个模板 × 20 关的玩家可见层；内部判定引擎、内容 schema、证据链与审计门禁保持不变。

---

## 0. 一句话结论

**关卡里不再有"工具卡"这一层**：没有卡片标题、没有手风琴、没有"先选模式/先声明规律/先拼积木"的设置步骤——打开哪一关，看到的就是这一关的题面；答案直接给在画布或面板上，填完自动判题、答对自动进下一关。

一轮做掉的三件事：

1. **删卡片**：宿主去掉 `ToolDock` 的卡头（模式卡 / 规则卡 / 构造块 / 参数旋钮 / 数据采集器 / 反例探测器）与手风琴，答案面板直接平铺；
2. **删设置**：pattern 关不再要"先点候选 chip 声明规律"，规律由画布填法**自动反推**；rule 关不再摆积木面板/程序列表，**画布点格子就是唯一输入**；argue 关不再有"先铺几块多米诺"的沙盒工具；
3. **画布独享**：pattern / rule 两关的右侧整列消失，画布占满整宽，只保留顶部失败横幅与底部「填完自动判题 / 重来」。

## 1. 玩家看到的变化

| 位置 | 改前 | 改后 |
|---|---|---|
| 关卡右栏 | 2~3 张可折叠"工具卡"，卡头写「模式卡」「规则卡」「构造块」等 | 没有卡片；只渲染这一关真正承载答案的面板，或干脆整块消失 |
| pattern 两关 | 卡里有「候选规律」chips + 变换按钮 + 补块槽位按钮 | **只剩画布**：点空格填字母，规律自动反推 |
| rule 两关 | 卡里有 6 个积木按钮 + 程序列表 + 删除/上移/下移 | **只剩画布**：点同排/同列的格子画路线 |
| argue 三关 | 多米诺沙盒 + 不变量探测面板 + 论证板 | **只剩论证板**：点一条依据即完成 |
| payment 关 | 两张卡（硬币台 / 反例探测器）需要来回展开 | 两块面板直接平铺，一次滚到底 |
| 交互量 | 每关要先"展开卡片"再操作 | 卡片层删除，展开动作归零 |

> pattern 关的画布「空格上点一下会放什么」仍然可读：预览字母来自当前已填内容反推出的规律，第一次点击落在循环表第一个字母上。

## 2. 实现口径（为什么这样改能保住门禁）

| 设计 | 做法 | 保住的东西 |
|---|---|---|
| 规律不再由玩家单独声明 | 新增 `deriveRuleFromRepairs(script, repairs)`：用可见格推出的候选规律去解释已填缺口，命中即写入规则并标记 `committed` | 证据链 `hypothesis` 检查点、**pattern 换表征迁移门**（产物仍带可翻译的 `patternRule`）、A6/A8 全不动 |
| 填错时反推不出规则 | `state.rule = null`，submit 走 repair-only 校验，报具体错格 | `pattern-mismatch` / `pattern-repair-incomplete` 等失败类与反馈文案照旧可达 |
| answerComplete 只看"缺口填满没有" | 去掉了"必须已提交规律"的前置 | 自动判题仍由 `validateArtifact` 判对错；填错也能立刻看到原因（不会卡在"没反应"） |
| rule 画布成为唯一输入 | 画布点格编译成展开版程序（转向 + forward×N + 自动收集），删掉积木面板 | 手拼"重复块"路径消失；`simple` 印章阈值（≤14 块）不再由 UI 追求，审计不依赖它 |
| argue 沙盒不再上屏 | 删多米诺/不变量探测面板；论证板内部仍自动采样 counts | 论证证书、证据链、失败类全部保留 |
| 内容层不动 | `tools[].titleKey/descriptionKey` 仍在 JSON 与 i18n 表里（内容体检要求非空） | `content:check`、i18n 中英成对、星图/日志/报告的工具标签不受影响 |

组件层面：删除 `ToolDock.vue`、`PatternTool.vue`、`RuleTool.vue`、`ConstructTool.vue`、`DominoTool.vue`、`InvariantProbeTool.vue`、`MetricsTool.vue`、`QueueMetricsTool.vue`；新增 `AnswerDock.vue` 按模板把工具规格映射到真正承载答案的面板（payment/network/schedule/frontier/distribute/counter/knob/tally/sampling/inference/sample）。

## 4. 门禁与验收

- `pnpm verify` 全绿：typecheck / lint / **393 单测** / 内容体检 / 关卡审计（A1–A11，5 条既有 A2 警告未新增）/ 打包体检 / build / size；

- pattern 单测改为验证"补满即自动反推规则"：k 关反推出 `ABB/none`，g13 的重复读法与镜像读法都能反推并通过换表征迁移门；
- 截图核对：pattern / rule 画布占满整宽；network / payment / winrate 面板平铺无卡片；argue 只剩论证板；1024×768 与 390×844 两档视口无横向溢出（`scrollWidth == clientWidth`）。

## 5. 已知限制

- **工具词汇还留在外围**：星图关卡卡片、思维日志、家长报告仍显示"模式卡 / 规则卡 / 构造块"等标签（那是记录与检索用的元数据，不是关卡设置）；如需统一改名，属另一轮文案工作。
- **rule 关的"漏收星星"失败类**从 UI 不再可达：画路线时会自动收集路过的星星；判定层的负例与失败反馈仍保留，审计不受影响。
- **简洁印章**（程序 ≤14 块）在 g13 手画路线时不可达（展开版最长 15 块）；该印章不是过关条件，审计也不校验。
- `MetricsTool` / `QueueMetricsTool` 删除后，调度/排队关的多次运行记录只在旋钮面板里看最近一次（关卡本来就只需一次）。
