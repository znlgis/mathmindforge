# 可玩性改造方案与实施记录

> 本文先回答"为什么现在不好玩、操作复杂、右侧有滚动条"，再记录**实际改了什么、怎么验收的**。
> 结论全部来自实测（Playwright + 源码定位）；每条带 `file:line`。
> 用户确认"全做、按推荐执行、接受交互形态变化"后进入实施，分三档落地：A 止血 → B 好玩 → C 有吸引力。

---

## 1. 怎么查的

- 起 dev server（`pnpm dev`，127.0.0.1:5192），用 Playwright 在 **1280×800 / 1366×768 / 1024×768 / 834×1112 / 390×844** 五个视口跑首页、星图、6 个关卡；
- 记录 `scrollHeight/clientHeight`、`getBoundingClientRect`、`elementFromPoint`，并做**注入式修复模拟**（只加 CSS，验证修法是否真的成立）；
- 用真实点击走完 `k-structure-pattern-path` 与 `g46-algorithm-payment`，统计点击数、阶段数、反馈时机；
- 截图对比画布哈希（验证"预览一下"是否真的有效果）。

**结论先行**：四个抱怨全部成立，但根因不是"游戏做得少"，而是**反馈没送到孩子眼前 + 交互藏在错误的位置**。

## 2. 改造前的问题清单（按影响排序）

### P0-1 右侧滚动条 = 工具区内部滚动，且反馈在滚动区外面

| 项 | 实测 |
|---|---|
| 现象 | 右下那条竖条不是页面滚动条：所有视口下 `documentElement.scrollHeight == clientHeight`，整页不滚 |
| 真正来源 | `apps/site/src/views/WorkshopView.vue:410` 的 `#level-dock` 带 `overflow-y-auto`；工具卡内容恒定 **928px**，可视只有 **666px**（1280×800）/ **634px**（1024×768）/ **356px**（390×844 手机 = 2.6 屏） |
| 最痛后果 | 失败提示横幅渲染在列表**最顶部**（`packages/toolkit-ui/src/ToolDock.vue:76-84`）。实测滚到底部点"验证结构"后，横幅在视口上方 **212~244px**，孩子看到的是"点了没反应" |
| 次生问题 | 底部操作条本身不遮挡（`dock.bottom == bar.top == 727`，零重叠），是 dock 的 `overflow` 把最后一张卡**裁掉**了：支付关最后一张卡高 505px 只露 298px |

### P0-2 1024×768（项目 e2e 默认视口）横向溢出、右栏被压扁

| 项 | 实测 |
|---|---|
| 现象 | `main.scrollWidth 1085 > clientWidth 1024`，右栏被压到 **184px**，按钮竖排、条高 121px |
| 根因 1 | `WorkshopView.vue:401` `flex-1` 缺 `min-w-0` → section 的 min-content 被 Phaser canvas 固有宽 **900**（`packages/templates/src/layout.ts:2`）顶住，锁死 901px |
| 根因 2 | `WorkshopView.vue:408` `lg:w-[420px]` 无 `shrink-0` → aside 被压到 184 |
| 根因 3 | `apps/site/src/style.css:45` `.game-host canvas` 无 `max-width:100%` |

### P1-3 "操作太复杂"是真的复杂：首关 14 次点击、6 段流程

| 关卡 | 实测通关成本 |
|---|---|
| `k-structure-pattern-path`（K 段首关） | **14 击**：观察 2 格 → 拼 A/B/B → 提交规律 → 3×(选格+放块) → 运行 → 验证结构 |
| `g46-algorithm-payment` | 9 击 + 1 数字输入 + 1 下拉 |

- **"运行"与"验证结构"语义重复**：`packages/templates/src/pattern/runtime.ts:280-337`，run 与 submit 走同一份 `validateArtifact`。
- **失败类被"缺步骤"吞掉**：实测 g46 先放 2 枚 4 元（超付 8 元）提交，提示的是"先完成工具步骤"，真实错误被跳过。
- **失败横幅会"粘住"**：误点提交后横幅停在"先点几格…"，补齐步骤后仍显示（`ToolDock.vue:53-67` 直接读 `snapshot.verdict`，工具动作不清理它）。

### P1-4 "没吸引力"：反馈全是延迟的，且没有声音

| 缺口 | 证据 |
|---|---|
| **全程零音效** | 音效基础设施齐全（`packages/game-kit/src/services.ts:18`、`packages/platform/src/web.ts:363-383`），但 `apps/` 与 `toolkit-ui/` **零调用**；Phaser 还显式关音频（`createGame.ts:32`）。`docs/03:153-157` 写的"每次 inspect 有轻音、语音引导一次"全未实现 |
| **"预览一下"是死按钮** | 实测点击前后画布哈希**完全相同**（`45fee1da0b95 → 45fee1da0b95`）；`pattern/runtime.ts:214-221` 只 emit 证据、不改任何状态 |
| **通关 1.8 秒自动跳走** | `WorkshopView.vue:29` `EXIT_DELAY_MS=1800`；完成面板只有"再做一次/回星图"，**没有"下一关"** |
| **每关的故事文案从未上屏** | 20 关 detail 里 `intro/prompt/done/retry` 齐全且已本地化，但 `WorkshopView.vue:384-385` 只渲染 `title` + `thinkingTarget` |
| **画布点不动** | 全仓 grep 无 `setInteractive`；`pattern/scene.ts:79-82` 注释明写"不接管指针"；观察入口是 36×36 数字按钮（低于 `docs/01:416` 的 ≥44px） |
| **"星图"是假的** | `nav.forge='思维星图'` 但 `ForgeView.vue` 是 20 张卡片平铺；`unlock.after` 定义却**从未被消费** |

## 5. 实施中额外修掉的真实缺陷

| 缺陷 | 现象 | 修法 |
|---|---|---|
| **"预览"会打掉已提交状态** | 玩家先点「用这条规律」再点「预览一下」，`pattern/setCycle` 把 `committed` 清成 false → 之后 `run` 报"先提交一条规律"、`submit` 报"先完成工具步骤：运行一次"，看着像游戏坏了 | `pattern/preview` 改为可携带 `cycle/transform`，预览时直接写规则；**只有预览的规则与已提交的不一致时才让旧提交失效**。`PatternTool` 预览不再先发 `setCycle`。`packages/game-kit/src/runtime.ts`、`pattern/runtime.ts`、`PatternTool.vue` |
| 注释里的中文整句触发 i18n 覆盖门禁 | `pnpm verify` 在 `i18n-coverage` 上失败（测试会扫描模板源码里的中文引号串） | 改成不带引号的表述 |

这条是验收脚本跑出来的：改完之后"提交→预览→运行→完成"整条链路才真的通。

## 6. 明确不改的东西

- **证据门/约束门/迁移门**的三段判定模型（产品核心资产）；
- 无分数、无计时、无排行（`docs/01` §5.6 的取舍）；
- 20 关的 `levelScript` 与内容 schema（本次只改呈现与交互，不改判定）。

## 7. 已知遗留

1. **20 关里 11 关首屏仍有滚动**（probe 类 754、knob 类 600~710、construct 类 629~659，g46/g1012-structure 叠放达 1004）。原因是单张工具面板本身就比 dock 可视高，不是布局 bug；主力首关已归零。若要全归零，需要给 probe/knob 面板做分步向导（把一张长表单拆成 2~3 屏）。
2. 画布命中区目前是整张纸带卡片（取最近格）；若要"只有格子本体可点"可再收窄。
3. `unlock.after` 在内容层目前全为空数组，所以星图是"顺序推荐"而非硬解锁；将来内容补依赖后 `isLevelUnlocked` 会立即生效。
