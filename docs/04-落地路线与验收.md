## 2. 里程碑

### M0 · 基座与行走骨架

**目标**：用一关（`k-structure-pattern-path`）把"外壳 → 关卡模块 → 纯运行时 → 工具台 → 画布 → 证据 → 存档 → e2e"整条链跑通。M0 不追求好玩，追求**骨架正确、门禁可用**。

**交付物**

1. workspace 骨架：`package.json`、`pnpm-workspace.yaml`、`tsconfig`、`eslint`、`vitest`、`playwright`、Tailwind、Vite；
2. 契约：`game-kit` 的 manifest/context/module/runtime/action/verdict/save 类型；
3. 内容：`content/ids` + 摘要/详情 schema + `loadLevel` + 第一关 JSON；
4. 运行时：`toolkit` 的 `pattern` 状态机 + `templates/pattern` 的 schema/logic/scene；
5. 画布：`canvas-kit` 的 `createGame` / `BaseScene` / `hitArea` / 主题 + Phaser 裁剪版接入；
6. 工具台：`toolkit-ui` 的 `ToolDock` + `PatternTool`（先只做一个工具）；
7. 外壳：路由、`HomeView`、`ForgeView`、`WorkshopView`、`debug` 桥；
8. 平台：IndexedDB 存档（`profileId` 键）、音频/TTS、`now()`；
9. 进度：`ProgressManager` 读写、`LevelProgress`、`completeLevel` 最小实现；
10. 门禁：`verify` + `content:check`（只校验 `SHIPPED_LEVEL_IDS` 子集）+ `audit:levels`（至少 A1/A1b/A3/A4 可跑）+ `check-size` + `pack-smoke`；
11. 测试：pattern 逻辑单测、第一关 e2e（autoplay + 无工具失败）、存档迁移单测；
12. 文档：`02` 契约与目录、`03` 第一关规格、`README` 快速开始。

**验收（必须全绿）**

- `pnpm install && pnpm verify` 通过；
- `pnpm e2e` 至少 3 条：第一关 autoplay 通过、无工具提交失败、刷新后完成状态还在；
- `pnpm size` 有基线数字（首屏、Phaser chunk、dist），并写进 `02`；
- 断网（DevTools offline）下第一关可玩、可存档；
- 代码里没有 `fetch` / `localStorage` 逃逸（lint 规则生效）；
- 第一关无工具提交返回 `missingEvidence`，不是"答案错误"。

**M0 完成情况（2026-10-31）**：`pnpm verify` 与 `pnpm e2e`（5 条）全绿；首关真实点击可通关；实测首屏 41.3 KB gzip、Phaser chunk 220.3 KB gzip、dist 1090.8 KB。实际实现、偏差与 M1 待办见 [M0 实现记录](05-M0实现记录.md)。

**明确不做**：其余 2 关、徽章、报告、编辑器、原生壳、英文内容。

**参考依赖**：无。M0 的所有决定会冻结为契约；后续改契约必须同步文档与测试。

### M1 · MVP 6 关

**目标**：证明"玩家必须使用工具才能通关"在五个模板、六个工具、四个主线上都成立。

**交付物**

1. 六关内容（`k-structure-pattern-path`、`k-data-tally`、`g13-algorithm-route`、`g46-algorithm-payment`、`g79-modeling-dispatch`、`g1012-modeling-winrate`）；
2. 五模板：`pattern / experiment / rule / construct / simulate` 的 schema/logic/scene 或面板；
3. 六个工具面板：pattern / rule / construct / knob / probe / counter；
4. 运行时：检查点、三道门、失败分类、多解校验、`actionsFor` autoplay；
5. 证据 v1：`EvidenceEvent`、聚合、四维信号初版、"思维轨迹"完成面板；
6. 反刷题审计自动项（A1/A1b/A2–A4/A6–A9）接入 `verify`；A5/A10 用 `manual-audit.md` 人工复核；
7. e2e：6 关 autoplay、3 关真实指针/键盘、每关无工具失败、证据落盘、深链；
8. 性能：1000 局模拟分片、构造搜索预算、关卡冷进入 ≤2 s；
9. 报告雏形：一页"这次你用了什么工具、失败→修正了什么"（不是正式家长报告）；
10. 用户测试第一轮（至少 5 名，覆盖 K/G1–3/G4–6 三段）。

**验收**

- 6 关 × 每关：≥2 解、≥3 负例、≥2 变体、无工具提交失败、反馈覆盖可达失败类；
- `pnpm verify` + `pnpm e2e` 全绿；
- 6 关 autoplay 各自 ≤ 30 s（instant 模式），真实操作路径可完成；
- 1000 局模拟 ≤ 1 s 且 UI 不冻结（分片）；
- 玩家测试中，至少 4/5 能在第二关出现"先观察/先调工具"的行为（记录在测试报告，不写死为 KPI）；
- 没有任何一关在去掉情境后只剩点选（人工复核 A5 + 审计）。

**M1 完成情况（2026-11-01）**：6 关、5 个模板、6 件工具全部接通；`pnpm verify` 全绿（89 单测 / 内容体检 / 关卡审计 / build / size），`pnpm e2e` 18 passed（6 关 autoplay、6 关无工具失败、3 关真实点击、断网/零外网、刷新保留）。实测首屏 42.4 KB gzip、Phaser chunk 220.3 KB gzip、dist 1227.2 KB。实际实现、内容数字与偏差见 [M0/M1 实现记录](05-M0实现记录.md)。

**明确不做**：第 7–20 关、argue、铺砌、双语内容、原生壳、报告导出、编辑器。

### M4 · v1.1 编辑器

**目标**：让玩家/教师用同一套模板设计一关，并且"可解性 + 反刷题"不会被绕过。

**交付物**

1. 编辑器 UI：模板选择、情境参数、工具配置、约束、反馈、变体、试玩；
2. 可解性校验：模板求解器 + 预算 + 证书检查；
3. 反刷题审计对玩家关卡同样生效；
4. 本机关卡库、导入/导出、二次校验；
5. 教师包：一关/一组关卡的导出与导入；
6. e2e：编辑→校验→试玩→导出→导入→再玩通。

**验收**

- 玩家能在 15 分钟内做出一个"可解 + 非纯选择 + 有变体"的关卡；
- 导入一个被篡改的关卡文件会被拒绝（schema/审计/大小上限）；
- 求解器超预算时明确返回"无法验证"，绝不假装通过；
- 编辑器不引入新网络请求、不执行任意脚本。

## 3. 工作分解（可并行的工作流）

| 工作流 | 负责 | 主要产出 | 依赖 |
|---|---|---|---|
| A 基座/契约 | 工程 | game-kit、content、platform、progress、存档迁移 | 无 |
| B 工具与模板 | 工程 | toolkit、toolkit-ui、canvas-kit、6 模板 | A |
| C 外壳与体验 | 前端/设计 | 路由、页面、星图、工具台接线、响应式、a11y | A、B |
| D 证据与报告 | 工程/产品 | evidence 聚合、徽章、日志、报告、导出 | A、C |
| E 内容 | 内容/设计 | 20 关 JSON、解/负例/变体、反馈、英文 | B、A |
| F 质量与发布 | 工程 | verify、audit、e2e、性能、打包、CI | A–E |
| G 用户研究与文档 | 产品 | 测试协议、记录、修复清单、文档 | C、E |

**并行纪律**：

- A 先冻结契约；B 可以按模块并行；E 在 B 的模板 schema 冻结后开工；
- 一个 PR 只改一个工作流的一个主题；内容 PR 与引擎 PR 分开；
- 共享文件（`game-kit` 契约、`content/ids`、`schemas.ts`）改动必须提前在任务板登记，避免多人同时改；
- 所有工作流共用一个 `verify`；谁弄红谁修，不把红留给下一个人。

## 5. 测试计划

### 5.1 单元与审计

| 对象 | 必测 |
|---|---|
| 六件工具 | 合法/非法动作、状态转移、产物指纹稳定、边界（空/满/越界） |
| 六个模板 | schema、reduce、validateArtifact、solve、actionsFor、applyVariant、失败分类 |
| 证据 | 事件裁剪、聚合、四维信号、徽章规则、报告生成、无事件/坏事件 |
| 存档 | 迁移链、字段 sanitize、未来版本回空、写失败提示、档案分键 |
| 内容 | M0 1 关 / M1 6 关 / M2 20 关（按 `SHIPPED_LEVEL_IDS`）、解/负例/变体、反馈覆盖、禁词、双语、难度轴 |
| 运行时 | 三道门、缺失证据、autoplay 与真实动作同路径、reset/订阅 |

**覆盖率不是目标**：目标是"每个判定分支都有测试 + 每个失败类都有负例"。审计脚本本身就是测试。

### 5.2 端到端矩阵

| 用例 | 覆盖 |
|---|---|
| 每关 autoplay | 全部关卡可完成 |
| 真实模式点选 | K1：inspect、setCycle、place、run |
| 真实规则拖拽 | G13A：放块、运行、变体 |
| 真实滑杆键盘 | G79D：方向键调参、运行、对比 |
| 无工具提交 | 6 关全部失败且提示缺失证据 |
| 失败→修正→通过 | 至少 2 关，验证修订链与日志 |
| 刷新/重开 | 存档保留、深链直达、档案切换（v0.9） |
| 双语 | 切英文后关卡内容/反馈/报告；刷新保持 |
| 报告 | 生成、打印样式、导出、导入 |
| 编辑器（v1.1） | 新建、校验、试玩、导出、导入、审计拒绝坏文件 |
| 断网 | 全程可玩，0 外网请求 |
| 移动/桌面视口 | 375×812、768×1024、1280×800 |

### 5.3 性能基准

- `scripts/bench-levels.mjs`：每模板 100 次判定/求解，输出 p50/p95；
- `scripts/bench-sim.mjs`：1000 局模拟的总时长与分片间隔；
- Playwright performance：首屏 `domContentLoaded` → 大厅可交互；关卡 `level:start` → `level:ready`；
- 回归阈值：p95 增长 >20% 报警；体积超预算即红。

### 5.4 可访问性

- 外壳/ToolDock：axe 无 critical/serious；键盘全流程；焦点可见；
- 画布：提供"状态摘要"文本与表格替代；不要求画布本身可读屏，但关键状态必须有一条等价通路；
- 对比度：正文 ≥4.5:1，大字号 ≥3:1；
- 动效：`prefers-reduced-motion` 下无大幅运动；
- 字号：跟随系统；英文不溢出按钮。

### 5.5 安全与隐私

- Playwright `page.route` 拦截并记录所有请求，断言只有本地资源；
- 导入文件：大小上限、严格 schema、二次审计、错误 JSON 不崩；
- 无 `v-html` 渲染外部内容；
- CSP 生效（Tauri 与 Web）；
- 存档清除/导出路径有测试。

## 6. 用户测试协议

### 6.1 对象与安排

- 每个学段 5–8 名；MVP 先做 K、G1–3、G4–6 三段；
- 低龄段允许家长在场，但**不提示**；成人只负责设备与安全；
- 单次 20–30 分钟；录音/录屏需监护人同意；不做人脸与姓名采集；
- 现场只观察，不教；卡住超过 90 秒才由主持人问"你现在在想什么？"。

### 6.2 任务

1. 第一次进入：能否自己找到"开始"；
2. 第一关：是否先观察再操作；卡住时是否会用工具提示；
3. 一关失败后：能否说出"哪里断了"，能否修改；
4. 迁移变体：能否把规则用到新图；
5. 完成一关后：能否用自己的话解释"这关在练什么"；
6. v0.9：报告页能否让家长/教师看懂"孩子做了什么"，而不是只看分数。

### 6.3 观察表（每次打勾/记录原话）

- 首次操作时间；首次运行前的观察动作数；
- 是否使用工具（而非乱点）；工具使用顺序；
- 失败后是否修改结构（而不是重复提交）；
- 是否有"这像考试/做题"的表达；
- 情绪：困惑/专注/兴奋/放弃；放弃发生在哪一步；
- 成人是否需要介入；介入原因；
- 对画面/文字/语音的理解障碍。

### 6.4 成功阈值（初始，M1 校准）

- ≥70% 的 K 段玩家在无成人提示下完成第一关；
- ≥60% 的 G1–3 玩家能完成路线关的当前地图；≥40% 能过 2 个变体；
- ≥50% 的玩家在第二关出现"先观察/先调工具"的行为；
- ≤20% 的玩家把游戏描述为"做题/考试"；
- 严重卡点（同一处卡住 >2 分钟）不超过 3 个/关，且有明确修法。

这些数字不是 KPI，而是**校准难度的工具**；不达标先改关卡与提示，不先怪玩家。

| 风险 | 概率/影响 | 缓解 |
|---|---|---|

| 单人/小团队排期 | 高/中 | M0 后按实测校准；工作流并行；MVP 先证机制 |

## 11. 项目级 Definition of Done

- 功能：符合 `01` 与 `03` 的规格；
- 正确性：单测 + 审计 + e2e 全绿；

- 体验：用户测试无明显卡点；无分数/排行/倒计时；
- 可访问性：键盘与读屏路径可用；
- 性能：预算内；
- 安全：0 外网请求、导入安全、隐私说明；
- 文档：契约/关卡/门禁同步；
- 发布：三端产物可安装，版本一致。

## 12. 结语

这套方案的核心不是"把 20 道题做成游戏"，而是把**思维工具**做成可操作、可失败、可修正、可记录、可审计的系统：

- 幼儿园补模式，小学写规则，高段拼构造，初中跑模型，高中验策略与讲边界；
- 通关靠工具产物，不靠背答案；
- 评价靠证据链，不靠正确率；
- 内容靠模板 + 变体，不靠题海；
- 工程靠门禁与审计，不靠"应该没问题"。

你确认范围后，我就按 M0 的 10 个 PR 开工；每个 PR 都带测试、文档更新与可验证的验收，不把"差不多"当完成。
