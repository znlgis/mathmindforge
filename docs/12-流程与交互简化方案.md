## 0. 一句话结论

**20 关里 12 关的规则首屏就能观察出来，但玩家平均要按 11.5 次才能通关（3 ~ 27 次）。多出来的部分不是玩法，是四类东西：**

1. **提示流程在复述内部步骤**：开场墨点气泡 + "第 n 步/共 N 步"进度条 + 情境条，同一份步骤名一屏出现三次；89 条检查点文案里 **0 条**在讲"什么算对/算错"。
2. **答案输入形式不直观**：下拉代替点选、先选槽再选块的两步操作、± 按钮累加 20 次、点了屏幕没变化的"查看指标"死按钮。
3. **门禁先于判定**：`submit` 先查"缺步骤"再校验答案，缺步骤横幅会顶掉真实错误；`network`/`frontier` 写进内容的失败反馈 **0 条可达**。

按本方案改完：**总交互量 229 → ~94 次（−59%）**，A 类关卡 3~6 次点击通关，证据链 / 三枚印章 / 迁移门 / 内容 schema 一个不少。

### P0-1 门禁先于判定，真实错误被"缺步骤"顶掉（影响 20 关，最严重）

- `packages/templates/src/pattern/runtime.ts:336-350`（pattern 自己又写了一遍）

### P0-2 提示流程在复述内部步骤（影响 20 关）

- 墨点气泡的文案 = `evidencePlan[].descriptionKey`（`WorkshopView.vue:80-84,126`），也就是**关卡把自己的内部检查点名字念给玩家**（"先真的铺一块试试"、"把证据挂到论证上"）。
- 同一份步骤名一屏出现 **3 次**：情境条 `WorkshopView.vue:525-532` + 进度条 `:557-575` + 气泡 `:577-588`。
- 气泡**不跟随真实进度**：`guideStep` 只在点"知道了"时 +1（`:435-441`），玩家先自己做完第 0 步，气泡就永久消失，后面 3 步永远不出现；最后一步按钮写"开始"，点下去的动作是"关闭教程"（`:436-439`、`:546`）。
- 全仓审计：20 关共 **89 条** `descriptionKey`，**0 条**在讲判定标准；3 条还是泄题（argue 三关直接把"统计黑白格或总格数"写出来，而这正是本关 thinkingTarget）。
- **无任何 e2e 依赖**（全仓 grep 无 `guide-bubble` 选择器），删改零测试风险。

> 结论：这不是"提示太少/太多"的问题，是**提示的内容根本不是提示**。规则可观察的关卡应当零提示；不可观察的关卡应当只解释判定标准，且只在失败后出现。

### P0-4 有四关玩家其实"没在填答案"（影响 4 关，最容易被忽略）

这个问题比"填得麻烦"更根本：**答案由系统算好，玩家只是把它抄一遍或点一下确认**。

| 关卡 | "答案"从哪来 | 玩家的动作 | 证据 |
|---|---|---|---|
| `k-data-tally` / `g13-data-weather` | 运行时已经把 20 / 14 个图形数好（`experiment/runtime.ts:77-90,383-393`），界面只把 chips 摆出来 | 逐类 +1 重敲一遍 20 次 | `TallyTool.vue:139-186` |

| `g1012-data-inference` | 工具直接把"区间重叠 → 差异不明确"写屏 | 读字 → 点按钮 | `InferenceTool.vue:53-79,103-105` |
| `g1012-modeling-winrate` | 胜率/区间一键生成 | 点一下"用这次数据下结论" | `SampleTool.vue:70-88` |

真正由玩家作答的只有 `queue` / `dispatch` 的参数向量，和 `argue` 的依据选择。

> **所以简化的第一步不是"少点几下"，而是先定义"这一关玩家到底答什么"**：
> - 数数是本关的认知目标 → 让玩家**真的数**（抽掉 chips，给数字框），而不是把答案抄一遍；
> - 判断才是本关的目标（inference/winrate）→ 抽掉工具代做的那一行，让玩家自己下判断；
> - 过程不是目标（sampling）→ 把"点一下"保留，但把两批波动显示出来，否则这一步没有教学价值。

## 3. 设计原则（六条）

1. **答题面 = 主界面**
   能观察直接理解的关卡，答案就画在玩家看的地方（画布 / 表格 / 棋盘 / 图），**点一次就填好**；工具面板退化为"说明 + 撤销"，不再是主操作区。

2. **提示只解释判定，不复述步骤**
   A 类关零开场提示；B/C 类关只在**失败之后**给一条"你的东西哪里不符合哪条判定"，且必须能指导下一步操作。删掉开场墨点气泡、"第 n 步/共 N 步"进度条。

3. **答案输入一步到位**
   一条规则：**一个可点区域 = 一次输入**。
   - 选项 ≤ 4 个 → chip / 循环点击（不用原生下拉）；
   - 数值 → 数字框或步进（不用累加 20 次）；
   - 多格同构 → 提供"照这样做"复制（不用手点 12 次）；
   - 点完必须**屏幕有变化**（否则就是死按钮）。

4. **门禁不吞错**
   `submit` 先 `validate`：有结构错误先报结构错误，缺步骤降级为第二行并**指向具体控件**（"在论证板上点「提交论证」"而不是"先完成工具步骤：提交论证证书"）。A1 审计（空产物必须给缺失证据）保持。

5. **最小交互 = 答案的自由度（下界，不能突破）**
   交互次数不能少于答案本身的自由度：`k-modeling-share` 是 4×2 计数矩阵（≥4）、`network` 要选 4 条边（=4）、`frontier` 只改 1 条边（=1）、`payment` 要付 6 元 + 构造反例（≈6）。
   **低于这个下界就不是"简化"，是系统替玩家做题**——例如把 k-share 压成"每个容器设一个总数"会丢掉种类维度，把 `g13-modeling-pack` 的 `minKinds:2` 直接变成必败解。
   所以本方案里每个目标值都按"自由度 + 1 次提交"核算过。

6. **证据由作答动作自动产生**

## 7. 验收方式

1. `pnpm verify` 全绿（typecheck / lint / test / content:check / audit / pack / build / size）。
2. `tsx scripts/audit-levels.ts` **A1–A8 全绿**（当前 5 条 A2 警告，改造后应消失或降级为已知项）。
3. **新增交互成本门禁**：e2e 断言每关真实通关点击数 ≤ §4 目标值（±1），防止以后又把步骤加回来。
4. **可观察性验收**：`network`/`schedule`/`frontier` 三个无画布关卡必须能在同一屏看到"约束灯 + 答案 + 完成"。
5. **失败反馈可达性验收**：逐关故意做错一次，断言横幅显示的是**内容 feedback 的 message**，而不是"先完成工具步骤"。
6. 五视口（1280×800 / 1366×768 / 1024×768 / 834×1112 / 390×844）无横向溢出、工具区无内部滚动。
7. **新增 UI 冒烟门禁（补现有门禁的盲区）**：每个工具面板的"关键动作"后，可见结果区必须发生变化（DOM 快照断言）；"点了没变化"的控件直接判失败。这条能一劳永逸拦住"死按钮"和"运行完没反馈"两类问题——现有 `audit:levels` 的 autoplay 走的是运行时、绕开了 UI，所以这些问题现在全绿。

## 8. 风险与说明

- **证据强度**：本轮全部是**静态审查**（源码 + 既有 e2e 序列），没有起 dev server 实测。§4 的"现状"数字可复现（e2e 序列展开），但建议实施前先用 Playwright 跑一遍基线，作为改造后的对比锚点。
- **最大风险在门禁语义**：T0-2/T0-4 动的 4 个模板共用运行时，`audit-levels` 的 A1/A8 与 autoplay 会立刻受影响。建议 Tier 0 单独成一个提交，跑绿门禁后再进 Tier 1。
- **e2e 是主要成本**：Tier 1 每个模板都会改 testid，59 条用例需要成批重写；建议按模板分批提交，每批跑一次全量 e2e。
- **不做的事**：不改无分数/无计时/无排行的产品取舍；不删证据链、印章、迁移门（只修它们的真实性与可达性）；不给规则可观察的关卡加任何新的引导。
- **`hasCanvas` 约束**：只有 `pattern`/`rule` 有 Phaser 画布（`forge.test.ts:94-106` 硬断言），其余 16 关的"图"必须用 Vue/SVG 在面板里画。
