## 3. MVP v0.5：6 关的选择与理由

MVP 不是"先做最容易的"，而是**用最少的关卡证明整条机制链**：

| 关卡 | 证明什么 |
|---|---|
| `k-structure-pattern-path` | 低龄段也能"先观察再动手"；模式工具产物可校验 |
| `k-data-tally` | 数据采集器在 5–6 岁可用；"采集→图表→结论"链路成立 |
| `g13-algorithm-route` | 规则程序 + 变体通行证；规则失败能定位到步骤 |
| `g46-algorithm-payment` | 构造 + 反例；多解与"贪心失手"可判定 |
| `g79-modeling-dispatch` | 参数真实影响指标；预算/覆盖率/等待时间的取舍 |
| `g1012-modeling-winrate` | 1000 局模拟 + 样本/区间；"证据不够"能被识别 |

- **模板**：pattern / experiment（两关）/ rule / construct / simulate（5 个）；`argue` 在 v0.9 补齐。
- **工具**：六件全部出现（pattern→关卡 1；probe→关卡 2、5、6；rule→关卡 3；construct→关卡 1、2、4；counter→关卡 4；knob→关卡 5、6）。
- **主线**：结构（1）、数据（2）、算法（3、4）、建模（5、6）。
- **不做**：铺砌（等距画布与不可能证书，v0.9）、调度/抽样/推断（内容成本高，v0.9）、编辑器（v1.1）。

**MVP 验收的硬条件**：

1. 6 关都能 `autoplay` 通关，且真实指针/键盘各至少 1 关；
2. 每关"无工具提交"必然失败；
3. 每关 ≥2 条有效解、≥3 个负例触发声明失败类、≥2 个变体；
4. 每关完成时写入证据，退出后可看到"思维轨迹"；
5. 6 关合计通过 `audit:levels`；`content:check` 全绿；
6. 首屏与关卡 chunk 在预算内；1000 局模拟 ≤ 1 s。

## 4. MVP 关卡详规

### 4.1 `k-structure-pattern-path` · 模式修补匠

| 项 | 规格 |
|---|---|
| 学段/主线 | K / 结构 |
| 模板 | `pattern` |
| 工具 | pattern（模式卡）+ construct（修补块盘） |
| 认知目标 | 从可见序列里找出重复单元，用规则预测并补全 |
| 时长 | 3–5 分钟 |
| 画布 | 一条 12 格的积木路；第 5–7 格被踩乱（空/错位）；角色在起点 |

**情境与初始状态**

- 序列（示意）：`A B B A B B ? ? ? A B B`（问号是破损格）；
- 可见格提供足够证据推断周期 `ABB`；破损格不给出答案提示；
- 备选块盘：A/B 两种形状，每种 4 块（多于所需，允许试错）；
- 角色只会在"路完整且规则一致"时走完全程。

**玩家动作**

1. 点若干格观察（`pattern/inspect`），界面显示"第几格 / 第几个单元"；
2. 在模式卡里框出单元、选周期（2/3/4）、改变换（无/镜像/平移一位）；
3. 预览规则（`pattern/preview`）——预测格逐格亮起，冲突格出现裂纹；
4. 从块盘拿块放到破损格（`construct/place`）；
5. 点"运行"（`run`），角色走路；走到破损格时按规则验证；
6. 通过后可选"再试一个"变体（换表征/换起点）。

**通关条件**

- 工具门：`patternRule` 已提交 + 至少 3 个修补块已放置；
- 约束门：12 格全部非空，且按玩家提交的规则生成时与所有可见格一致；
- 迁移门：至少一个变体通过（MVP 的默认变体为"形状代替颜色"或"起点平移一位"）。

**多解**

- 若可见序列允许周期 2 与周期 4 同时成立（设计上给一个这样的变体），两者都接受；
- 修补块的摆放顺序、块盘里的选择不影响判定；
- 至少 2 条有效解：①周期 3 + 按单元补全；②在歧义变体里周期 2/4 的另一种合法规则。

**失败类与反馈**

| 失败类 | 触发 | 反馈（示例） | 焦点 |
|---|---|---|---|
| `pattern-no-observation` | 未 inspect 就提交 | "先点几格看看它是怎么重复的，路会告诉你答案。" | 高亮带子 |
| `pattern-cycle-wrong` | 规则与可见格冲突 | "第 4 格本来和你的规则不一样：你的单元是 ABB，可那里是 A。" | 冲突格裂纹 |
| `pattern-repair-incomplete` | 破损格还有空 | "还有两格没铺，角色会掉下去。" | 空格闪烁 |
| `pattern-mismatch` | 补的块与规则不符 | "第 6 格你放了 A，但按你的规则它该是 B。" | 该格震动 |
| `pattern-transfer-failed` | 当前通过、变体失败 | "换成形状以后，规律没有变，只是颜色换成了形状。" | 变体缩略图 |

**证据检查点**

1. `observe`：inspect ≥ 2 次；
2. `hypothesize`：提交一条模式规则；
3. `construct`：放置 ≥ 3 块；
4. `run`：至少运行 1 次；
5. `generalize`：变体通过（可选印章）。

**变体**

| id | 轴 | 变化 |
|---|---|---|
| `v-relabel` | representation | A/B 从颜色变成形状（圆/方），规则不变 |
| `v-shift` | transfer | 序列从第 2 格开始重复，单元相同 |
| `v-ambiguous` | structure | 允许两种周期都成立（用于多解） |

**画面与声音**

- 低龄：块大、颜色对比强；每次 inspect 有轻音；裂纹有"咔"声但无失败音效；
- 语音引导一次（可关）："先看看它是怎么排的"；
- 角色不掉血、不结束；失败只停在缺格/裂纹处。

**自动通关与 fixtures**

- 黄金解 1：inspect 4 次 → setCycle(`[A,B,B]`) → 放 3 块 → run；
- 黄金解 2（歧义变体）：setCycle(`[A,B]`) → 放对应块 → run；
- 负例：①周期写成 `[A,B]`（在非歧义关冲突）；②少放一块；③放错块；④未观察直接提交。

### 4.2 `k-data-tally` · 分类小站

| 项 | 规格 |
|---|---|
| 学段/主线 | K / 数据 |
| 模板 | `experiment`（确定性数据源，无随机） |
| 工具 | probe（采集器）+ construct（统计条） |
| 认知目标 | 把一堆东西按类数清楚，用图/条记录数量，并说出最多/最少 |
| 时长 | 4–6 分钟 |
| 画布 | 无画布；用大卡片与 CSS 动画（更适合低龄与键盘/读屏） |

**情境与初始状态**

- 一筐 20 个图形：圆 6、方 5、三角 6、星 3（示例）；
- 采集器每次"抓一把"5 个，放入"已采集"托盘；点 4 次采完；
- 统计条区有 4 个空柱，每柱可用 "+1" 按钮/拖块加高；
- 结论区：选"最多"或"最少"，再选一个图形，并显示当前样本量。

**玩家动作**

1. 点"采集一把"（`probe/sample`），看托盘与表格增加；
2. 采满 20 个后，按类把统计条搭到正确高度（`construct/place`）；
3. 点一个统计条查看数量（`probe/focus`）；
4. 选结论并提交（`probe/claim` + `submit`）。

> 产物类型：`dataset`（采集数据）、`tally`（统计条，不是 `placement-set`）、`claim`（count-compare）。`requiredToolArtifacts = ["dataset","tally","claim"]`。

**通关条件**

- 工具门：dataset 样本量 = 20；TallyArtifact 存在；claim 存在；
- 约束门：TallyArtifact.counts 与数据集逐类一致（validator 按"类别→数量"匹配，不按列位置）；claim 是 count-compare 且与数据一致（"最多"遇到圆/三角并列时，必须把另一个写进 tiedWith）；
- 迁移门：一个变体（5 类/24 个/水果代替图形）通过。

**多解**

- 统计条可以按任意列顺序摆放（TallyArtifact.order 可不同，counts 必须一致）；
- 结论可以选"最多"或"最少"，只要与数据一致；
- 至少 2 条有效解：不同列序/不同结论方向。

**失败类与反馈**

| 失败类 | 触发 | 反馈 | 焦点 |
|---|---|---|---|
| `probe-not-collected` | 未采集就提交 | "筐里还有好多没数呢，先抓几把。" | 采集按钮呼吸 |
| `probe-sample-small` | 样本 < 20 就写结论 | "你才数了 10 个，还不能说谁最多。" | 样本量标签 |
| `construct-chart-count-wrong` | 柱高与数量不符 | "方形有 5 个，你的柱子有 6 格。" | 错的那根柱 |
| `probe-claim-mismatch` | 结论与数据相反 | "数据里三角和圆一样多；说'最多是三角形'只对了一半。" | 结论卡 |

**证据检查点**

1. `observe`：至少采集 1 次并查看表格；
2. `construct`：搭出统计条；
3. `claim`：提交一个与数据一致的结论；
4. `generalize`：变体通过。

**变体**

| id | 轴 | 变化 |
|---|---|---|
| `v-five-kinds` | representation | 4 类 → 5 类（增加"心形"），总数 20→25 |
| `v-fruit` | representation | 图形 → 水果图片（程序化绘制） |
| `v-tally` | representation | 柱状条 → 5 个一组的计数符号 |

**低龄适配**

- 每个动作都有语音与图例；文字 ≤ 14 字；
- 采集按钮 ≥ 96×96；统计条 +1 按钮也足够大；
- 没有倒计时；采错了可以清空重来（`probe/clear` 有长按确认）。

**自动通关与 fixtures**

- 黄金解 1：采集 4 次 → TallyArtifact counts {circle:6, square:5, triangle:6, star:3} → claim { kind:'count-compare', direction:'most', category:'circle', tiedWith:['triangle'], n:20 }；
- 黄金解 2：TallyArtifact order 改为 三角/圆/方/星（counts 不变）→ claim { kind:'count-compare', direction:'least', category:'star', n:20 }；
- 负例：①样本 10 就 claim；②柱高 6/6/6/2；③claim"最多是星"；④未采集直接提交。

### 4.3 `g13-algorithm-route` · 规则工程师·路线

| 项 | 规格 |
|---|---|
| 学段/主线 | G1–3 / 算法 |
| 模板 | `rule` |
| 工具 | rule（规则卡） |
| 认知目标 | 用顺序、重复与条件拼出可执行规则，并让规则适应同类地图 |
| 时长 | 5–8 分钟 |
| 画布 | 7×7 网格；角色、墙、星星、终点 |

**初始状态**

- 起点 (0,0)，面朝东；终点 (6,6)；3 颗星星在 (0,3)、(3,1)、(5,5)；墙在 (1,2)、(2,2)、(4,4)、(5,1)、(3,5)；
- 块面板：前进、左转、右转、收集、重复 n 次（可嵌套）、如果前方是墙则右转；
- 程序上限 24 块，执行上限 200 步；超过步数即 `rule-loop`；
- 第一张地图可自由试；通过后出现"变体通行证"（2 张未见地图）。

**变体**

| id | 轴 | 变化 |
|---|---|---|
| `v-walls` | structure | 墙的位置改变，星星/终点不变 |
| `v-rotate` | structure | 起点/终点/朝向旋转 90°，同一拓扑 |
| `v-transfer` | transfer | 地图改为"先下楼再上楼"，仍是同一类可解空间 |

**通关条件**

- 工具门：程序 artifact 已提交 + 在当前地图至少运行一次；
- 约束门：当前地图执行成功（收齐 3 星、到终点、不撞墙、不超步）；
- 迁移门：2 张变体地图也成功（同一程序，不修改）。

**多解**

- "展开写"与"用重复/条件"都接受；validator 只看执行结果；
- 至少 2 条程序：①展开序列；②重复 + 条件；
- 简洁印章：块数 ≤ 关卡声明的简洁线（可拿可不拿）。

**失败类与反馈**

| 失败类 | 触发 | 反馈 | 焦点 |
|---|---|---|---|
| `rule-not-run` | 未运行就提交 | "先让它走一遍，看看哪一步会停。" | 运行按钮 |
| `rule-out-of-bounds` | 撞墙/出界 | "第 6 步撞到墙：重复块把角色又送回了边界。" | 失败步高亮 |
| `rule-loop` | 超步数 | "程序一直在绕圈：重复里没有让位置改变。" | 循环块闪烁 |
| `rule-missed-item` | 到终点但漏星 | "你到终点了，可第 2 颗星还在路上。" | 漏星位置 |
| `rule-deadlock` | 前方是墙但无转向 | "第 4 步前面是墙，规则里没有'如果'。" | 墙与当前块 |
| `rule-not-general` | 当前通过、变体失败 | "这张地图多了一堵墙；你的规则在第 3 类地图失效。" | 变体地图缩略 |

**证据检查点**

1. `observe`：至少单步运行 1 次或查看轨迹；
2. `construct`：程序块 ≥ 3；
3. `run`：当前地图运行；
4. `revise`：若失败，至少修改 1 块再运行；
5. `generalize`：变体通过。

**自动通关**

- 黄金解 1：展开的 18 块程序；
- 黄金解 2：重复 + 条件的 11 块程序；
- 自动通关逐块 `rule/place`、`rule/commit`、`rule/run`，与真实操作同一路径。

**负例**

1. 向前走 3 步撞墙（out-of-bounds）；
2. 重复里没有改变状态（loop）；
3. 走到终点但漏星（missed-item）；
4. 当前地图通过，但去掉"如果前方是墙"后变体失败（not-general）。

### 4.4 `g46-algorithm-payment` · 最少枚数支付

| 项 | 规格 |
|---|---|
| 学段/主线 | G4–6 / 算法 |
| 模板 | `construct` |
| 工具 | construct（硬币摆放）+ counter（反例探测器） |
| 认知目标 | 在"恰好付清 + 枚数最少"的约束下构造方案，并发现贪心何时失效 |
| 时长 | 6–10 分钟 |
| 画布 | 收银台：目标金额、面额盘、硬币堆、枚数/金额计数 |

**初始状态**

- 面额 `[1, 3, 4]`，目标金额 6；
- 玩家从面额盘拿硬币放到柜台，显示总额与枚数；
- "贪心演示"按钮展示 4+1+1=3 枚；"最优检查"不直接给答案，只显示"还能更少吗？"；
- 反例面板：可选目标 1–20 与面额集合 `[1,3,4,5]` 的子集，点"测试贪心"比较贪心枚数与最优枚数；勾选失效前提。

**通关条件**

- 工具门：payment artifact + counterexample artifact + 至少一次测试；
- 约束门：①支付恰好 6 元且枚数 = 2（最优）；②反例中贪心枚数 > 最优枚数、失效前提选择正确，且目标金额或面额集合至少一个不同于主任务（禁止用主任务参数冒充反例）；
- 迁移门：一个变体（不同面额/目标）通过。

**多解**

- 硬币顺序不影响；反例可以有多种（例如目标 8/[1,3,4,5]、目标 10/[1,3,4] 等，但不能复用主任务的目标 6/[1,3,4]）；
- 至少 2 条有效解：不同反例组合；硬币顺序只算同一解的不同排列，不单独计数；
- "一次就付到最优"不作为印章：它依赖操作史，只作为运行记录里的一条证据（revisionCount = 0），不影响通关与判定。

**失败类与反馈**

| 失败类 | 触发 | 反馈 | 焦点 |
|---|---|---|---|
| `construct-not-optimal` | 付清但枚数大于最优 | "你付清了，但用了 3 枚；还能用 2 枚付清吗？" | 枚数计数 |
| `construct-overpay` | 总额超过目标 | "4+4 是 8 元，柜台只要 6 元。" | 总额 |
| `counter-not-tested` | 未测试就提交反例 | "先让贪心在这个例子上跑一遍。" | 测试按钮 |
| `counter-invalid` | 反例里贪心并不差 | "这个例子里贪心也用了 2 枚，它还不是反例。" | 对比表 |
| `counter-reused-main` | 反例复用主任务的目标/面额 | "这个例子和主任务一样，换一个目标或面额再试。" | 反例面板 |
| `counter-wrong-premise` | 前提选错 | "不是因为'没有 1 元面额'——这个例子里有 1 元。" | 前提选项 |

**证据检查点**

1. `construct`：至少放 2 枚硬币；
2. `run`：至少检查 1 次枚数/金额；
3. `counter`：至少测试 1 个候选反例；
4. `revise`：若被判定非最优，至少改一次再提交。

**变体**

| id | 轴 | 变化 |
|---|---|---|
| `v-denoms` | constraint | 面额改为 `[1,5,8]`，目标 12（贪心 8+1×4，最优 5+5+1+1） |
| `v-weights` | representation | 硬币 → 砝码/积木，规则相同 |
| `v-cap` | constraint | 目标改为 10、面额保持 `[1,3,4]`、最多 3 枚：贪心 4+4+1+1=4 枚会失手，最优 3+3+4=3 枚 |

**反馈与教学立场**

- 不直接说"贪心是错的"，而说"贪心在这个例子里不是最优"；
- 反例的失效前提只给 4–6 个选项，每个都是可检验的命题；
- 完成后报告写"你找到了一个让贪心失手的例子，并指出了它依赖的前提"。

**负例**

1. 付 6 元用 4+1+1（非最优）；
2. 付 8 元（超付）；
3. 反例直接复用主任务目标 6/[1,3,4]（按 `counter-reused-main` 拒绝，即使贪心确实较差）；
4. 前提选"没有 1 元面额"（实际有）。

### 4.5 `g79-modeling-dispatch` · 城市调度员

| 项 | 规格 |
|---|---|
| 学段/主线 | G7–9 / 建模 |
| 模板 | `simulate` |
| 工具 | knob（参数旋钮）+ probe（指标采集） |
| 认知目标 | 把"收运"抽象成变量与指标，在预算内做取舍，并用第二个种子验证稳健性 |
| 时长 | 8–12 分钟 |
| 画布 | 6 个站点的环形小镇；车库、车辆、时间轴、指标条 |

**模型（确定性，种子只影响需求）**

- 站点 0–5 环形，车库在 0；相邻行驶 4 分钟；每站服务时间：1 队 2 分钟、2 队 1 分钟（并行卸货）；
- 车辆容量 10；班次 60/90/120 分钟；车辆 0 分钟开始装货，装货 5 分钟；
- 需求表（固定，不随机）：seed A（101）=[3,2,4,3,2,4]，seed B（202）=[2,4,3,2,4,3]，合计均为 18；
- 参数：车辆数 1–4、服务队 1–2、路线模式（单环/双区/快线）、班次；
- 指标：覆盖率（已服务需求/总需求）、平均等待（按需求单位加权，从班次开始到该单位被服务）、成本、未服务量；
- 成本 = 车辆 25/辆 + 服务队 10/队 + 行驶分钟 × 0.5；预算 120；
- 目标：seed A 覆盖率 ≥ 90%、平均等待 ≤ 18 分钟、成本 ≤ 120；seed B 覆盖率 ≥ 85%、等待 ≤ 20。

**玩家动作**

1. 先运行一次默认参数（看到指标）；
2. 调车辆数/服务队/路线/班次（`knob/set`）；
3. 再运行（`knob/run`），对比指标（`knob/compare`）；
4. 达标后换种子再跑一次（`run`，变体 v-seed）；
5. 提交方案（`submit`）。

**通关条件**

- 工具门：至少 2 次运行；至少 1 次指标对比；参数向量 artifact；
- 约束门：种子 A 下覆盖率 ≥ 90%、等待 ≤ 18、成本 ≤ 120；
- 迁移门：种子 B 下覆盖率 ≥ 85%、等待 ≤ 20（防止只对一个种子调参）。

**多解**

- 候选可行解（目标，不是既成事实）：
  - A：3 辆车 + 1 队 + 单环 + 120 分钟班次；
  - B：2 辆车 + 2 队 + 双区 + 120 分钟班次；
  - 容量 10 × 2 = 20 ≥ 需求 18，B 也能覆盖；实际指标由 audit:levels 的模拟器验证，内容必须至少保留 2 组通过 threshold 的解，否则改目标或改参数范围，不允许伪造；
- validator 只看指标与预算，不看"标准参数"；
- 简洁印章：用更少的车/更低的成本达标。

**失败类与反馈**

| 失败类 | 触发 | 反馈 | 焦点 |
|---|---|---|---|
| `sim-not-run` | 未运行就提交 | "先让车跑一天，看看时间花在哪。" | 运行按钮 |
| `sim-budget` | 成本 > 120 | "第 4 辆车把成本推到 132；等待只降了 1 分钟。" | 成本条 |
| `sim-coverage` | 覆盖率 < 90% | "站点 3 的需求有 4，你的车装不下第二圈的货。" | 站点 3 |
| `sim-wait` | 等待 > 18 | "大部分等待发生在第二圈：车回到站点 2 时已经过了 22 分钟。" | 时间轴 |
| `sim-overfit-seed` | 种子 A 过、B 不过 | "换一天需求后，第 2 辆车不够用了。" | 种子 B 对比 |
| `sim-variable-missing` | 方案未记录指标就提交 | "还没有数据能说明这个方案更好。" | 对比表 |

**证据检查点**

1. `observe`：默认参数运行并查看指标；
2. `hypothesize`：调整至少 1 个参数；
3. `run`：至少 2 次运行并对比；
4. `generalize`：换种子通过。

**变体**

| id | 轴 | 变化 |
|---|---|---|
| `v-layout` | structure | 环线改为"两条支线 + 一个换乘点" |
| `v-demand` | constraint | 需求分布从均匀变为"商业区高、住宅区低" |
| `v-seed` | transfer | 同结构不同需求种子（稳健性检查） |

**反馈与教学立场**

- 指标不是分数，是"决策—证据"的显示器；
- 失败反馈指出"哪个变量导致哪个指标"，不说"再想想"；
- 报告写"你先加车辆，后来发现瓶颈在服务时间，于是改服务队"。

**负例**

1. 4 辆车 + 快线，成本 112；
2. 1 辆车 + 单环，覆盖率 61%；
3. 种子 A 达标、种子 B 覆盖率 78%；
4. 未运行直接提交。

### 4.6 `g1012-modeling-winrate` · 胜率实验室

| 项 | 规格 |
|---|---|
| 学段/主线 | G10–12 / 建模 |
| 模板 | `experiment` |
| 工具 | knob（策略参数）+ probe（对局采样/区间） |
| 认知目标 | 设计资源分配策略，用大样本对局与区间估计判断"是否真的更好" |
| 时长 | 8–12 分钟 |
| 画布 | 无画布；策略面板 + 对局统计表 + 胜率/区间图（SVG） |

**模型（确定性，种子控制对手与噪声）**

- 开局把 100 资源一次性分给攻击 attack / 防守 defense / 经济 economy（三者之和 = 100，步长 5）；
- 第 r 回合（r = 1..10）的经济存量：eco(r) = economy * 0.1 * (r - 1)；对手同理；
- 玩家攻击分：A(r) = attack * (1 + 0.03 * eco(r)) * noise(seed, r, 1)；玩家防守分：D(r) = defense * (1 + 0.03 * eco(r)) * noise(seed, r, 2)；
- 对手攻击/防守分：OA(r) = opp.attack * (1 + 0.03 * oppEco(r)) * noise(seed, r, 3)，OD(r) 同理（side=4）；
- 每回合：A(r) > OD(r) 玩家得 1 分；OA(r) > D(r) 对手得 1 分；两边可同时得分或都不得分；
- 10 回合后分高者胜，平局按 0.5 胜计；noise 用 mulberry32(seed * 10007 + r * 131 + side) 映射到 [0.9, 1.1]；
- 对手原型：快攻 50/20/30、龟缩 20/50/30、经济 30/30/40；按 weight 归一化后用种子抽取；
- 采样：100 / 500 / 1000 局，按 50 局分片跑，显示进度；统计胜率 + Wilson 95% 区间；
- 第二种子复验：同一策略在 seed B（202）上重跑 1000 局；
- **校准**：55% / 52% 的目标与示例 claim 是设计目标，不是拍脑袋的既成事实；M1 用参考实现跑出基线后校准系数与阈值，content:check 会用种子重算 claim 并拒绝不一致的数值。

**玩家动作**

1. 设策略（滑杆）；
2. 采 100 局看方向（`probe/sample`）；
3. 加大样本到 1000（`probe/sample`），看区间；
4. 若区间跨过 50%，改策略或继续采样；
5. 提交策略 + 数据 + 结论（`submit`）。

**通关条件**

- 工具门：策略 artifact + dataset n ≥ 1000 + claim（胜率/区间/样本量）；
- 约束门：种子 A 胜率 ≥ 55%，Wilson 下界 > 50%；
- 迁移门：种子 B 胜率 ≥ 52%（避免只对一个种子过拟合）。

**多解**

- 多组参数可以达标（例如偏经济 vs 均衡），validator 只看数据；
- 至少 2 条解：不同参数向量 + 不同种子；
- 简洁印章：用更少的采样达到同样结论（n ≥ 600 且区间下界 > 50%）。

**失败类与反馈**

| 失败类 | 触发 | 反馈 | 焦点 |
|---|---|---|---|
| `exp-not-run` | 未采样就提交 | "还没有一局数据，先跑 100 局看看方向。" | 采样按钮 |
| `exp-sample-small` | n < 1000 却下结论 | "100 局里赢 56 局，但区间太宽，还不能说稳定超过基准。" | 样本量 |
| `exp-below-baseline` | 胜率 < 55% | "当前策略 51%；经济投入在第 5 回合后被快攻压制。" | 策略滑杆 |
| `exp-claim-beyond-ci` | 结论超出区间 | "你写'至少 60%'，但区间上界只有 56%。" | 结论卡 |
| `exp-overfit-seed` | 种子 A 过、B 不过 | "换一批对手后胜率掉到 50%；策略对快攻太敏感。" | 种子 B |
| `exp-not-collected` | 没有 dataset artifact | "结论要挂在这次采样上，不能凭感觉。" | 数据表 |

**证据检查点**

1. `hypothesize`：先设一个策略；
2. `run`：至少采样 100 局；
3. `observe`：查看胜率/区间；
4. `claim`：提交带样本量与区间的结论；
5. `generalize`：第二种子复验。

**变体**

| id | 轴 | 变化 |
|---|---|---|
| `v-opponents` | constraint | 对手比例从 1:1:1 改为 5:3:2 |
| `v-resources` | structure | 起始资源 100 → 80，回合数 10 → 12 |
| `v-representation` | representation | 滑杆 → 表格输入（键盘友好） |

**模拟性能**

- 1000 局 × 10 回合 ≈ 1 万次简单计算；50 局/片，20 片；每片后让出主线程；
- 结果可缓存（同参数 + 同种子），重复采样不重复算；
- 统计用 Wilson 区间，纯函数，单测覆盖边界（0/1、小样本、n=1000）。

**负例**

1. 100 局、胜率 56%、直接 claim "稳定超过 60%"；
2. 1000 局、胜率 51%、下界 48%；
3. 种子 A 56%、种子 B 50%；
4. 无 dataset 直接提交。

## 5. 其余 14 关规格（v0.9）

> 每关给出：情境、工具、通关操作、失败类、变体轴。详细 levelScript 在内容实现时按 `01` 的作者模板补齐；这里锁定不可变的设计意图与验收口径。

### 5.1 `k-algorithm-train` · 规则小火车

- **情境**：一条 6 格直线轨道，小火车从车头出发，经过 3 颗星星到站；轨道上有 1 个岔口（左/右）。
- **工具**：rule（只开放"前进/左转/右转/收集/重复 2 次"）。
- **通关**：程序在当前轨道与 1 张同构变体上都收星到站；程序 ≥3 块且运行过。
- **失败类**：`rule-not-run`、`rule-missed-item`、`rule-out-of-bounds`、`rule-not-general`。
- **变体**：岔口方向镜像（structure）；星星位置换位（structure）。
- **低龄适配**：指令卡是图章，不需要读长句；运行速度放慢，每步有音效。

### 5.2 `k-modeling-share` · 公平分点心

- **情境**：4 个盘子、12 块点心；要求每盘一样多、没有剩余。
- **工具**：construct（把点心拖到盘子；有"每人一盘"的等式条）。
- **通关**：4 盘各 3 块，总数 12；任意分配顺序都接受；变体（3 盘 9 块/5 盘 10 块）通过。
- **失败类**：`construct-gap`（有盘空）、`construct-constraint`（数量不等）、`construct-overpay`（多发/少发）。
- **变体**：盘数/点心数改变但保持整除（structure）；盘子→小袋（representation）。
- **多解**：先每盘 1 块循环发，或先拿 3 块放一盘；最终状态相同，动作路径不同。

### 5.3 `g13-structure-symmetry` · 对称补墙

- **情境**：一面 6×6 花砖墙，右半边缺失；左半边给出对称轴与图案。
- **工具**：pattern（选对称/平移/旋转规则）+ construct（补砖）。
- **通关**：补全后整墙关于给定轴镜像对称；至少 1 个变体（斜轴/旋转对称）通过。
- **失败类**：`pattern-cycle-wrong`（规则选错）、`pattern-mismatch`（砖位错）、`pattern-transfer-failed`。
- **变体**：竖轴→横轴（representation）；镜像→旋转 90°（transfer）。
- **多解**：对称轴两侧可以选择不同的砖色配对，只要对称性成立。

### 5.4 `g13-modeling-pack` · 公平分装

- **情境**：3 个箱子、9 件玩具（球/积木/书各 3 件）；每箱要"数量相同 + 类别齐全"。
- **工具**：construct。
- **通关**：3 箱各 3 件且每箱至少 1 种不同类别；约束面板实时显示"数量/类别"。
- **失败类**：`construct-gap`、`construct-constraint`、`construct-overlap`（重复放同一件）。
- **变体**：4 箱 12 件（structure）；"每箱必须有一本书"（constraint）。
- **多解**：同一类别组合的不同排列都接受。

### 5.5 `g13-data-weather` · 天气记录站

- **情境**：14 天的天气符号（晴/云/雨/雪），每天一张卡；要做一张天气统计，并回答"哪种天气最多/雨天比雪天多几天"。
- **工具**：probe（逐日采集/表格）+ construct（统计条）。
- **通关**：14 天全部记录；统计条与数据一致；结论与数据一致。
- **失败类**：`probe-not-collected`、`construct-chart-count-wrong`、`probe-claim-mismatch`。
- **变体**：14→21 天（structure）；符号→文字（representation）；"雨天比雪天多几天"（constraint）。
- **证据**：采集顺序、是否先看表格再下结论。

### 5.6 `g46-structure-tiling` · 铺砌挑战

- **情境**：等距投影的"三维"造型；用菱形/长条块铺出投影。第 1 阶段给完整投影；第 2 阶段只给 3D 目标；第 3 阶段给"不可能图形"，要求给出不变量证书。
- **工具**：construct（摆放/旋转/翻转）+ counter（不变量测试）。
- **通关**：第 1/2 阶段覆盖且不重叠；第 3 阶段选择一个不变量（棋盘染色/面积/边界计数），证书检查通过。
- **失败类**：`construct-gap`、`construct-overlap`、`construct-out-of-bounds`、`construct-impossible-unproven`、`construct-counterexample-invalid`。
- **变体**：完整投影→仅 3D 目标（representation）；旋转目标（structure）；不可能图（constraint/transfer）。
- **实现注意**：不引 3D 引擎；等距投影 + 网格坐标；不可能证书用染色计数检查器。
- **为什么 v0.9**：等距画布与证书检查器是单独一块工作量；MVP 用支付关验证 `construct` 与 `counter` 的通用能力。

### 5.7 `g46-modeling-queue` · 排队模型

- **情境**：一个服务台，顾客按种子到达；可调窗口数（1–3）与服务速度；目标平均等待 ≤ 8 分钟、成本 ≤ 预算。
- **工具**：knob（窗口/速度/班次）+ probe（等待分布/利用率）。
- **通关**：预算内等待达标；换种子仍达标；至少 2 次运行对比。
- **失败类**：`sim-budget`、`sim-wait`、`sim-coverage`（未服务率）、`sim-overfit-seed`。
- **变体**：到达率加倍（constraint）；服务台→两个队列（structure）；预约制（transfer）。
- **证据**：先运行再调参；是否看了等待分布而非只看均值。

### 5.8 `g46-data-invariant` · 不变量侦探

- **情境**：给若干棋盘/图形区域，问"能否用 1×2 骨牌铺满"；有的能，有的不能。
- **工具**：counter（染色/计数测试）+ probe（查看区域数据）+ 论证板（v0.9 轻量版）。
- **通关**：对不能铺的区域，选对不变量（黑白格数量不等）并给出计数证据；对能铺的区域，给出一个构造。
- **失败类**：`counter-invalid`、`counter-wrong-premise`、`argue-claim-unsupported`。
- **变体**：棋盘→楼梯形（representation）；骨牌→L 形（constraint）；染色→边界计数（transfer）。
- **立场**：这不是"证明题考试"，而是"找到那个不随操作改变的量"。

### 5.9 `g79-structure-network` · 路网连通

- **情境**：6 个城镇，需修路使任意两镇可达；预算只够 8 条路；且"去掉任意一条路仍连通"（冗余）。
- **工具**：construct（加边）+ counter（去掉一条边测试连通）。
- **通关**：边数 ≤ 8、连通、去掉任意一条仍连通；至少 1 个变体（城镇位置/单行约束）。
- **失败类**：`construct-gap`（不连通）、`construct-constraint`（边数超）、`counter-invalid`（测试的不是割边）。
- **变体**：6→8 镇（structure）；允许单向路（constraint）；预算收紧（constraint）。
- **多解**：不同的 8 边冗余网络都接受；简洁印章给边数更少的解。

### 5.10 `g79-algorithm-schedule` · 课程表调度

- **情境**：5 门课、3 位老师、3 间教室、4 个时段；约束：同一老师同一时段不能两课、同一教室不能两课、某课必须在上午、某老师连续两节不能排。
- **工具**：construct（把课放进时段×教室格）+ counter（检验贪心/某条约束为何卡住）。
- **通关**：全部课程排入、约束全满足；至少 1 个变体（新增一门课/老师不可用）。
- **失败类**：`construct-overlap`、`construct-constraint`、`construct-gap`、`counter-wrong-premise`。
- **变体**：新增课程（structure）；老师请假（constraint）；时段改为 3 个（constraint）。
- **多解**：不同合法课表都接受；简洁印章给"改动最少"的解（可选）。

### 5.11 `g79-data-sampling` · 抽样调查

- **情境**：一个 500 人的"小镇"（含不同区域/年龄的分布），要估计"支持某方案的比例"；只能访问 100 人。
- **工具**：probe（抽样/表格/区间）+ knob（样本量/分层方案）。
- **通关**：样本估计与总体真值误差 ≤ 5 个百分点；说明抽样方法；至少 1 个变体（分布偏斜）下仍成立。
- **失败类**：`probe-sample-small`、`probe-claim-out-of-ci`、`probe-misread`（只在一个区域抽样）、`probe-not-collected`。
- **变体**：总体分布偏斜（constraint）；分层抽样（transfer）；样本量 100→200（structure）。
- **证据**：是否先看总体分布再选抽样方法；结论是否带区间。

### 5.12 `g1012-structure-invariant` · 结构不变量

- **情境**：图/棋盘结构，要求证明"某类构造不可能"或"必须满足某不变量"；可用的依据：奇偶、染色、面积、边界计数。
- **工具**：counter（构造反例/检验不变量）+ probe（数据/计数）+ 论证板。
- **通关**：证书包含主张、依据、证据、适用边界；检查器验证不变量在给定区域上成立且足以排除构造。
- **失败类**：`argue-claim-unsupported`、`argue-invariant-false`、`argue-case-incomplete`、`argue-bound-wrong`。
- **变体**：棋盘→图（representation）；奇偶→染色（transfer）；"不可能"→"必须至少 N 步"（constraint）。
- **边界**：只支持有限族不变量与可计算检查；不承诺通用定理证明。

### 5.13 `g1012-algorithm-frontier` · 算法边界关

- **情境**：给 8/12/16 个城市的小规模路径问题；玩家可运行暴力、贪心、启发式三种策略，观察时间与解质量随规模的变化。
- **工具**：knob（规模/策略参数）+ probe（运行时间/解质量/样本）+ counter（构造贪心失手的实例）+ 论证板。
- **通关**：给出"贪心不是总是最优"的反例；用 3 个规模的数据说明成本增长；给出一个"足够好但不必最优"的策略与适用边界（可检验的证书 + 实证数据）。
- **失败类**：`argue-claim-unsupported`、`argue-bound-wrong`、`argue-counterexample-invalid`、`probe-sample-small`。
- **变体**：规模上限（structure）；时间预算（constraint）；"必须精确解"→"允许近似"（transfer）。
- **立场**：不要求"通关最优"，要求"解释为什么不必最优"。

### 5.14 `g1012-data-inference` · 统计推断站

- **情境**：两组玩家/两种方案的对局数据；要判断"新方案是否真的更好"，而不是被噪声骗。
- **工具**：probe（采样/均值/区间）+ knob（样本量/分组）+ counter（偏差/反例样本）。
- **通关**：报告两组均值差与区间；结论与区间一致；指出至少一个可能的偏差来源；至少 1 个变体（样本偏斜）下不误判。
- **失败类**：`probe-sample-small`、`probe-claim-out-of-ci`、`probe-misread`、`exp-overfit-seed`。
- **变体**：样本量 50→500（structure）；分布偏斜（constraint）；配对数据（transfer）。
- **证据**：是否看区间而非只看均值；是否报告样本量；是否指出偏差。
