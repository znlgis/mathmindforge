## 2. 高价值修复（按影响排序）

### 2.0 P0：生产构建白屏（dev e2e 全绿也发现不了）

| 项 | 内容 |
|---|---|
| 现象 | `pnpm e2e`（dev）59 条全绿；`pnpm e2e:dist`（生产产物）每条都超时，页面 `#app` 为空 |
| 根因 | CSP 用**正则替换 `</head>`** 注入，而 `apps/site/index.html` 的注释里恰好写了 `</head>` 字面量。替换命中注释内部，把 `<script type="module">` 与注入的 CSP meta 一起塞进注释，同时吃掉了真正的 `</head>`，HTML 结构被破坏 |
| 为什么门禁没拦住 | 体积门禁只量文件大小；dev e2e 走的是 Vite dev server，不经过 `transformIndexHtml` 的生产注入路径 |
| 修复 | 改成 Vite 的**标签描述符**注入（`transformIndexHtml: () => [{ tag: 'meta', attrs: {...}, injectTo: 'head' }]`），由 HTML parser 负责插入；注释里的字面量也一并去掉 |
| 防回归 | `check-size.mjs` 增加"剥掉注释后必须仍有 module script 与 CSP meta"的产物结构检查；`csp.test.ts` 断言注入方式为标签描述符而非字符串替换；CI 的 preview job 本来就跑 `e2e:dist`，现在真的能覆盖这条路径 |

**教训**：对 HTML 做字符串级注入等于把解析器的工作交给运气。只要一段用户可见的 HTML 里可能出现目标字面量（注释、文案、代码示例），就必须交给真正的 HTML parser。

## 3. 质量门禁加强（防止同类问题再回来）

### 3.1 `content:check`

- 摘要/详情 **id、标题、模板、学段/主线、工具列表**逐项比对；
- 20 关六个英文字段（`titleEn / thinkingTargetEn / introEn / promptEn / doneEn / retryEn`）必须齐全、**零中文、零全角标点**；
- 禁词分级：伤害性词（失败/惩罚/笨蛋/输了/淘汰/粗心/扣分/排名/倒数）→ **错误**；建议替换词（必须/聪明/笨）→ **警告**；
- 变体 id 唯一、轴合法；证据检查点 id 唯一且 `require` 非空；`unlock.after` 不得引用自己或不存在的关卡；
- `manualAudit.reviewedAt` 必须是 ISO 日期；`--require-all` 要求 20/20。

### 3.2 `audit-levels`

| 项 | 检查 |
|---|---|
| A1 | 无工具提交必须失败且给出 `missingEvidence` |
| A1b | 空产物必须被**结构反馈**拒绝，不能当成"缺证据" |
| A2 | `actionsFor` 至少含一个非选择动作（新增；只有一种时警告） |
| A3 | ≥2 条有效解且产物 JSON 互不相同（新增去重检查） |
| A4 | 负例触发声明失败类；可达失败类 ⊆ `feedback`；≥3 类有负例 |
| A6 | 变体 ≥2 且可解析；迁移门逐条可过 |
| A8 | `evidencePlan` ≥2 阶段；`autoplay` 真的走到 `passed`、检查点全满足、产生过证据草稿（新增运行时断言） |
| A5/A10 | 只检查人工复核记录存在与日期合法，判断留给人 |

### 3.3 `pack:check`

改成只检查**仓库里真实存在**的东西：脚本齐全、workspace、站点入口与零外链、vendor 与 MIT 许可、20 关摘要/详情的 id 一致、英文字段齐全、首关 `manualAudit`。原生壳目录不存在时给**提示**而不是假装通过。

### 3.4 `vitest.config.ts`

纳入 `apps/site/src/**/*.test.ts`。此前外壳里写的测试**根本不会执行**——这比没有测试更糟，因为它制造"已经测过了"的错觉。

## 6. 已知缺口（明确不做假账）

### 6.1 本轮已收口（原缺口 → 处理方式）

1. **英文反馈（P1）**：模板与内容里的中文整句原本直接当 key，英文界面回退中文。处理：
   - 工具面板的错误消息统一走 `t()`（之前 `error = result.message` 直接渲染，绕过了翻译）；
   - 英文兜底表补齐模板侧的**整句**（含场景短句与带 `{need}` 占位符的句子）；
   - 新增 `packages/templates/src/i18n-coverage.test.ts`：扫描模板源码里的中文整句，缺英文即失败（已用"删掉一条译文"验证过会红）。
   **仍未收口**：纯拼接片段（如 `" / 守 "`、`" 条边 · 成本 "`、`schedule-runtime` 的 `'冲突：' + a + '/' + b`）无法查表，需要把模板改成"整句模板 + 参数"才能翻译——那是一次会动 5 个 runtime 的重构，留给下一轮。
2. **休眠缺陷（P1）**：`construct/experiment/simulate` 的部分模式在 `validateArtifact` 里忽略 variant。处理：新增 `shared/variant-script.ts`（`scriptForVariant`），network / schedule / frontier / sampling / inference / queue 六条路径统一先应用 `variant.patch` 再校验。当前这些模式的 `transferVariants` 仍为空，属于"提前修好、暂无回归可测"的预防性修复。
3. **`queue-unserved` 不可达（P2）**：`runQueue` 无接待上限，`served` 恒等于到达数。处理：从 `reachableFailureClasses` 移除，并在源码里写明原因；内容里的 `feedback` 条目保留（`content:check` 只要求"可达类 ⊆ feedback"，多余条目无害）。要让它真正可达，得先改排队模型（打烊后不再接待），属于玩法决策。
4. **`argue` 双份 `actionsFor`（P2）**：runtime 里另抄了一份多米诺坐标（`v@(0,1)`），与 logic 的 `h@(removed+1)` 不一致。处理：runtime 改为委托 `logic.actionsFor / transferVariants / transferFailureClass`，单一事实来源。

### 6.2 仍然未解决

1. **拼接片段文案**：见 6.1-1 末段，需模板重构；
2. **原生壳 / 真实用户测试 / 发布流水线**：受环境限制（本机无 Rust 与 Android SDK）与人力限制，仍未完成，见 [发布检查清单](09-发布检查清单.md)；
3. **首屏体积**：英文兜底表让首屏 gzip 从 52.2 KB 涨到 **65.5 KB**（预算 85 KB）。仍在预算内，但再往里塞译文就会顶到上限；下一步应把 en 表拆成懒加载 chunk（需要把切语言变成异步），属独立改动。

## 7. 验收命令与结果

```bash
pnpm verify      # typecheck / lint / 322 单测 / content:check / audit:levels / pack:check / build / size
pnpm e2e         # 59 条（Chromium，dev server）
pnpm e2e:dist    # 59 条（生产产物 + preview，覆盖 CSP 注入后的真实 HTML）
```

本轮最终跑法（收尾修复后重跑）：`pnpm verify` 全绿（3.3s，322 单测 / 内容体检 / 关卡审计 / 打包体检 / build / size）；`pnpm e2e` 59 passed；`pnpm e2e:dist` 59 passed（40.4s）。
三条命令缺一不可：**dev e2e 测不到生产注入**（P0 就是这么漏掉的），而 `verify` 只测单测与产物体积。

审查方法上的三条经验：
**（1）"测试没被 include"和"没写测试"一样危险**——先确认测试真的在跑（本轮发现外壳测试写了但 include 没覆盖）；
**（2）文档里没有实现的东西要删掉或标注**，否则下一轮审查会把计划当现状，继续在上面垒代码；
**（3）"dev 能跑"不等于"产物能用"**——凡是构建期改写 HTML/CSP/资源路径的逻辑，必须有针对产物的验证。
