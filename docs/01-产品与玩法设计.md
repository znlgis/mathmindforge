# 《数思工坊》产品与玩法设计

> 本文回答：玩家在每一分钟里做什么、系统如何判定"他在使用思维工具"、评价与报告如何避免变成分数、玩家/教师如何设计关卡。

---

## 1. 玩家与场景

| 维度 | 设定 |
|---|---|
| 年龄 | 5–18 岁，五个学段：K（5–6）、G1–3、G4–6、G7–9、G10–12 |
| 设备 | 平板/手机触屏为主；学校电脑（鼠标+键盘）必须可用；桌面端窗口可缩放 |
| 单次时长 | 一关 3–10 分钟；一次会话建议 10–20 分钟；不设倒计时、不催下线 |
| 使用场景 | 家庭自由探索；课堂 15 分钟"思维工具课"；课后挑战 |
| 成人角色 | 家长/教师看"证据报告"，不看正确率；教师可用本机档案与导出包 |
| 语言 | 中文优先；界面与内容双语（英文懒加载），v1.0 内容双语 |

**首次进入**只问一件事："你现在大概几年级？"（可跳过）。它只决定推荐的起始星图位置，**不锁死内容**——任何学段都可以自由进入，因为这是"工具工坊"，不是年级课程。

## 2. 世界与界面隐喻

不是"宠物小屋"，而是**一间会长的工坊**：

- **工坊大厅**：六件工具挂在墙上；每件工具有使用痕迹（划痕、便签、样本瓶），显示玩家用它做过什么。
- **思维星图**：5 条横带（学段）× 4 条纵线（主线）的关卡星图；节点是关卡，连线是"工具依赖"。星图不是课程进度条，而是"你走过哪些结构、哪些边界"。
- **今日工作台**：推荐下一关（基于证据缺口，不是难度分数）、上次未完成的关卡、自由工坊入口。
- **档案柜**：思维日志、徽章、家长/教师报告入口（长按 3 秒）。
- **可选向导「墨点」**：一个几何墨点，只在卡住时出现，说一句结构性提示；不评价、不卖萌、不打断。可在设置里关掉。

视觉方向：**蓝图 + 纸艺 + 黄铜**。米白纸面、深墨蓝、黄铜色、青绿工具色；网格与图纸纹理用 CSS/Phaser 程序化绘制，零位图；标题字体拉丁优先、CJK 回落到 Noto Sans SC/雅黑（避免 BambooBuddy 踩过的弯引号全角问题）。

## 3. 六件思维工具（产品规格）

每件工具在界面上是一个"工具卡"，展开后是操作面板。工具不是按钮，而是**有状态、有产物、可校验**的编辑器。

### 3.1 模式卡 `pattern`

**它让玩家做什么**：从一段序列里圈出重复单元，声明周期与变换，然后用这个规则去补全/预测/修补。

**界面**：一条可横向滚动的"带子"（积木路/瓷砖墙/音符序列），下方是"单元框"和"周期选择"；玩家点两个位置框住一个单元，系统给出候选周期；右侧预览"按这个规则，后面 3 个应该是什么"。

**操作**：
- `pattern/inspect`：点任意位置查看它的"第几位/属于第几个单元"（观察证据）；
- `pattern/setCycle`：选单元、周期、变换（无/镜像/旋转/平移一位）；
- `pattern/preview`：让规则在带子上"跑一遍"，亮出预测位置；
- `pattern/commit`：把规则作为产物提交（不是答案，是工具产物）。

**产物**：`PatternRule { tokens: string[]; period: number; transform: 'none' | 'mirror' | 'rotate' | 'shift' }`。

**可观察后果**：规则跑过时，预测块会逐格亮起；如果与现有序列冲突，冲突格变成裂纹并停留在那里，玩家能看见"从哪一格开始断的"。

**失败类**：`pattern-cycle-wrong`、`pattern-incomplete`、`pattern-transfer-failed`、`pattern-no-observation`。

**防止点选通关**：只选周期不算通关；必须用规则实际补全至少一个缺口，且系统会换一个"换表征"的变体（颜色改形状/方向改位置）再验一次。

### 3.2 规则卡 `rule`

**它让玩家做什么**：用指令块拼一段可执行程序，让角色在地图上自动收集/到达/避开障碍，并且**对同类变体地图也成立**。

**界面**：左侧地图预览（Phaser 画布），右侧块面板：移动、转向、收集、如果…则…否则…、重复 n 次、重复直到…。中间是程序序列，可拖拽、缩进、删除。底部"运行/单步/重置"。

**操作**：`rule/addBlock`、`rule/moveBlock`、`rule/setParam`、`rule/deleteBlock`、`rule/run`、`rule/step`、`rule/commit`。

**产物**：`Program { blocks: Block[]; maxSteps: number }` + 每次运行轨迹 `Trace`（逐步状态、失败步号）。

**可观察后果**：单步时角色走一步，程序块高亮；撞墙/循环/漏收集时，画面停在失败步，轨迹面板指出"第 6 步：重复块第 2 次，方向朝墙"。

**失败类**：`rule-out-of-bounds`、`rule-loop`、`rule-missed-item`、`rule-deadlock`、`rule-not-general`（带失败变体 id）。

**防止点选通关**：通关必须提交可执行程序并真的运行；"变体通行证"要求同一程序在 2–3 张未见地图上通过，否则只算"当前地图能走"，不算完成。

### 3.3 构造块 `construct`

**它让玩家做什么**：在网格/平面/等距视图上放置、旋转、翻转块，满足覆盖、对称、连通、预算、不重叠等约束；有的关要构造出目标，有的关要证明目标不可能。

**界面**：画布是网格或等距地板；底部/右侧是块盘（形状、颜色、数量限制）；支持拖拽、点选、旋转、翻转、撤销、重做；约束以"检查项"列表实时显示（覆盖 12/12 ✓，重叠 1 ✗）。

**操作**：`construct/place`、`construct/remove`、`construct/rotate`、`construct/flip`、`construct/undo`、`construct/check`、`construct/submit`。

**产物**：`PlacementSet { pieces: { id, shape, x, y, rot, flip }[] }`。

**可观察后果**：实时约束灯；提交时逐条检查，失败的那条高亮并指出冲突格；多解时给出"另一种摆法"的缩略提示（不是答案，是鼓励多样性）。

**失败类**：`construct-overlap`、`construct-gap`、`construct-out-of-bounds`、`construct-constraint`、`construct-impossible-unproven`、`construct-counterexample-invalid`。

**防止点选通关**：必须真的摆放；不可能关的"提交"是提交一份**不可能性证书**（不变量选择 + 证明检查），不是选一个"不可能"选项。

### 3.4 参数旋钮 `knob`

**它让玩家做什么**：把情境抽象成可调变量（车辆数、站点数、班次、资源投入），调参后运行模拟，观察指标变化，直到在预算内达标。

**界面**：一组带数值读数的滑杆/步进器（每个都有单位、范围、当前值、上一次值），旁边是"运行"按钮；下方是最近几次运行的小表（参数 → 指标）。滑杆支持键盘方向键。

**操作**：`knob/set`、`knob/run`、`knob/compare`、`knob/reset`、`knob/commit`。

**产物**：`ParamVector { values: Record<string, number> }` + 每次运行的 `RunMetrics`。

**可观察后果**：地图上车辆/队伍动起来；指标条与等待时间直方图变化；超预算的项变红；换一个种子再跑，提示"这次也达标吗？"。

**失败类**：`sim-budget`、`sim-coverage`、`sim-wait`、`sim-variable-missing`、`sim-overfit-seed`。

**防止点选通关**：必须至少运行一次并观察指标；"只看参数不运行"不能提交；完成要求在预算内达标，且换种子仍达标（防碰运气）。

### 3.5 数据采集器 `probe`

**它让玩家做什么**：采样、记录、看表/散点/区间，用数据支持或否定一个假设。

**界面**：一个"采样"按钮（每次 N 个样本，带进度）、数据表（可排序、可高亮）、散点/柱状/区间图（SVG，不依赖图表库）、"写结论"区域（从证据句式里选 + 填数值，不是自由作文）。

**操作**：`probe/sample`、`probe/clear`、`probe/focus`（高亮某个点/组）、`probe/claim`（提交结论：方向 + 数值 + 样本量）。

**产物**：`Dataset { seed, n, values, groups }` + `ClaimInput`（`count-compare` / `stat` / `difference` 三类可校验结论）。

**可观察后果**：样本点逐个落到图上；样本量太小时区间很宽，图上用阴影表示不确定性；结论超出区间时系统标出"证据不够"。

**失败类**：`probe-sample-small`、`probe-claim-out-of-ci`、`probe-not-collected`、`probe-misread`（把相关当因果/只看均值）。

**防止点选通关**：结论必须绑定到本次采样；"没采样就写结论"必失败；采样按钮不是一次性动画，数据表与图是真实状态。

### 3.6 反例探测器 `counter`

**它让玩家做什么**：构造一个候选实例，测试某个规则/贪心/猜想是否失效，并指出失效的前提。

**界面**：一个小型实例编辑器（面额集合、棋盘、图、参数组），"测试"按钮，结果面板显示"该规则在此例上失败/成立"，并要求勾选"它违反了哪条前提"。

**操作**：`counter/edit`、`counter/test`、`counter/annotate`（失效前提）、`counter/commit`。

**产物**：`Counterexample { instance, ruleId, failedPremise, witness }`。

**可观察后果**：测试时规则逐步执行到失败点；失败的局部高亮；若构造的例子其实不构成反例，系统指出"这个例子仍然满足规则，因为…"。

**失败类**：`counter-invalid`、`counter-not-minimal`（可选，不阻断）、`counter-wrong-premise`。

**防止点选通关**：必须自己构造实例；系统会随机生成同类规则/实例做鲁棒性检查，防止"背一个反例"。

### 3.7 论证板（边界关的提交面，不是第七件工具）

在 `argue` 模板里，玩家把工具产物组装成一份**可检验的论证证书**：

- 主张（Claim）：从关卡给定的主张类型里选，并填参数；
- 依据（Warrant）：奇偶性 / 面积 / 染色 / 交换论证 / 样本区间 / 上界构造；
- 证据（Evidence）：挂接反例、数据集、运行指标、构造尝试；
- 适用边界（Scope）：说明在什么条件下成立、什么条件下失效。

论证板不是作文框：每一栏都有可检验的结构；校验器会真的跑反例、检查不变量、核对样本量。v0.9 先在高中两关使用。

## 4. 六个关卡模板（引擎原语）

模板决定"画布长什么样、工具有哪些、判定怎么做"，内容 JSON 决定"这一关的具体参数"。模板必须**数据完备**：同一模板能承载玩家编辑器生成的新关卡，不需要为每关写新代码。

| 模板 | 画布 | 默认工具 | 判定核心 | 对应主线 |
|---|---|---|---|---|
| `pattern` | 序列带/墙/路 | pattern + construct | 规则补全 + 换表征迁移 | 结构 |
| `rule` | 网格地图 | rule + counter | 程序执行 + 变体泛化 | 算法 |
| `construct` | 网格/等距板 | construct + counter | 约束满足 + 多解 + 不可能证书 | 结构/算法/建模 |
| `simulate` | 简化城镇/队列 | knob + probe | 预算内指标 + 换种子稳健 | 建模 |
| `experiment` | 对局/数据面板（可无画布） | probe +（按关卡：knob / construct / rule） | 大样本胜率/模型 + 证据充分 | 数据/算法 |
| `argue` | 结构/图表 | counter + probe + 论证板 | 证书可检验 + 边界解释 | 边界 |

模板与工具是多对多：一个模板可以开放多件工具；一件工具可以出现在多个模板里。工具的实现只写一次。

## 5. 核心机制

### 5.1 三道门与"缺失证据"

完成判定（**2026-11 修订**，见 [流程与交互简化方案](12-流程与交互简化方案.md)）：

~~~text
submit()
 ├─ 一件产物都没有                            → Verdict{ passed:false, missingEvidence:[...] }
 ├─ 有产物：先跑约束/多解判定
 │    ├─ 失败                                  → Verdict{ passed:false, failure:{...}, missingEvidence:[...] }
 │    └─ 通过，但 checkpoints 未满足            → Verdict{ passed:false, missingEvidence:[...] }
 ├─ 如果迁移门失败                             → Verdict{ passed:false, failure:{ class:'transfer-failed', variantId } }
 └─ 否则                                      → Verdict{ passed:true, stamps:[...], metrics }
~~~

**为什么改**：原来"缺步骤"排在结构校验前面，玩家答错时看到的永远是"先完成工具步骤：<内部检查点名>"，
真实错误（"你的规则和左边墙对不上"）被顶掉；network / schedule / frontier 写进内容的失败反馈
在正常 UI 里 0 条可达。改后结构错误优先，缺步骤降级为第二行并指向具体控件。

**检查点的语义**（同一修订）：`checkpoint` 只记录"答案状态的事实"（填了几块、跑过一次、对照过数据），
**不再要求玩家按固定顺序走仪式**，也不再上屏成"第 n 步 / 共 N 步"进度条。

`requiredToolArtifacts` 是**内容自检字段**：`content:check` 用它保证"必用产物确实有工具产得出"，
运行时不再做第二道门（历史上也从未实现，文档与代码在此对齐）。

界面不显示清单式命令，而是把反馈落到世界里的具体位置：

- 缺产物 → 说清"哪一块还没填 / 哪一条依据还没选"；
- 答错 → 直接给结构错误（失败类的 `message` + `hint`，`feedback.focus` 指向冲突格/断点）；
- 缺迁移 → 变体通行证翻出一张没见过的地图。

### 5.2 多解与三枚思想印章

通过约束门即可通关；在此之上最多得到三枚**非竞争性**印章：

| 印章 | 判定 | 展示 |
|---|---|---|
| 约束印章 | 满足全部硬约束 | 必得 |
| 简洁印章 | 构造步数/块数 ≤ 关卡声明的简洁线，或程序块数 ≤ 参考值 | 可选 |
| 迁移印章 | 通过 2–3 个变体（含换表征） | 可选 |
| 论证印章 | 论证/反例证书被校验器接受 | 边界关可选 |

印章不是分数，不累计成等级；它们进入证据链与徽章规则。界面只显示"这关你拿到了哪几枚印章"，不显示"比谁多"。

### 5.3 结构性反馈（失败类 → 人话）

每个失败类在内容里必须有一条 `feedback`：`{ message, hint, focus }`。文案规范：

- 说**结构**：`你的规则在第 3 类地图会撞墙，因为重复块没有检查前方`；
- 说**条件**：`这个摆法在边界上留下了一格缺口，换一块更长的砖试试`；
- 说**模型**：`你把等待时间当成常数了，但它会随车辆数变化`；
- 不说：`再仔细点 / 粗心 / 算错了 / 失败了`。

`focus` 指向界面元素（高亮哪个约束、哪一步、哪个变体），让反馈可操作。文案与失败类一起进 `content:check`：每个失败类必须有反馈；反馈里禁止通用伤害性词表。

### 5.4 提示系统（三级，不泄题）

1. **环境提示**（自动，3 秒）：高亮可操作区域、工具呼吸、首次进入的 10 秒演示；
2. **工具提示**（玩家点"墨点"）：解释这件工具怎么用、当前产物哪里不完整，不给出正确参数；
3. **示范提示**（连续两次同类失败后）：给出一个**不同情境**的微示范（"上次有个学徒遇到规则循环，他把重复次数改成'直到收集完'，你看看像不像"），不是本题答案。

提示使用记录为证据（提示后仍能迁移，比"零提示"更能说明理解；不做惩罚）。设置里可关闭自动提示。

### 5.5 运行、观察、修正的节奏

- 每次运行都产生 `RunRecord`（参数/产物摘要、指标、失败类、时间），保留最近 10 次；旧记录折叠进"历史"。
- 失败后，界面不弹"重试"模态，而是把失败点留在画布上；玩家改一块、再运行，上一轮失败点以半透明残影显示，形成"修订链"。
- 一次会话结束时（退出关卡），如果发生过"失败→修改→通过"，在思维日志里生成一条 `修正回放`：失败类 → 改了什么 → 结果。这是评价的核心素材。

### 5.6 无失败、无计时、无排行

- 没有生命值、没有倒计时、没有分数、没有排行榜、没有"今日排名"；
- 通关不消耗资源，失败不扣任何东西；
- 唯一的时间相关设计是"建议休息"（20 分钟一次，可关）与"本周回顾"，不制造流失压力；
- 不设连续天数与断签惩罚；可以有"本周来过几次"的中性统计，但不做目标。

### 5.7 动态难度（四轴，不是数字轴）

玩家卡住时，系统按证据调整的是**提示与变体**：

- 连续两次同类失败 → 换一个更小/更规则的变体（结构复杂度 −1），保留同一思维目标；
- 迁移连续失败 → 给出"换表征"的中间桥梁（如从颜色序列换成方向序列的对照）；
- 长时间无操作 → 只高亮环境，不给答案；
- 从不卡住 → 追加"换约束"变体，而不是加大数字。

每次难度调整都写证据事件（`scaffold`），报告里可以说明"这一关在提示后完成，下一步建议独立尝试换表征变体"。

## 6. 评价：四类证据与画像

### 6.1 证据事件

运行时只写**事实**，不写评价：

~~~ts
interface EvidenceEvent {
  v: 1;
  id: string;
  at: number;                 // 注入时钟
  profileId: string;
  levelId: LevelId;
  variantId: string;
  phase: 'observe' | 'hypothesize' | 'construct' | 'run' | 'result' | 'revise' | 'generalize' | 'argue';
  tool?: ToolId;
  action: string;             // 'pattern/setCycle' 等
  artifact?: { kind: string; digest: string; summary: string };
  outcome?: 'info' | 'pass' | 'fail';
  failureClass?: string;
  metrics?: Record<string, number>;
  revision?: number;          // 同一关内第几次修订
  scaffold?: 'none' | 'env' | 'tool' | 'demo';
}
~~~

指纹 `digest` 只是稳定哈希，用于去重与回放，不是安全哈希。证据日志**不记录**自由文本输入（避免儿童隐私），玩家的"想法便签"单独存储且可一键清除。

### 6.2 四维信号（初始口径，M1 校准）

| 维度 | 信号（全部来自事件） | 三档描述（报告用语） |
|---|---|---|
| 结构识别 | 观察事件先于首次提交；模式规则补全；换表征变体通过 | 还在试错 → 会先看规律 → 能换一种表示也认出结构 |
| 规则构造 | 程序产物存在；当前地图通过；变体通过数；失败后修订 | 能写出可执行规则 → 能让规则适应变体 → 会从失败轨迹定位规则断点 |
| 模型修正 | 旋钮运行次数；指标达标；换种子仍达标；失败→改参数→达标的链路 | 会调参数 → 会用指标验证 → 会解释哪个变量导致哪个后果 |
| 边界论证 | 有效反例数；不可能证书；样本量/区间合格；结论不越界 | 能找到反例 → 能说明失效条件 → 能给出"足够好"的边界理由 |

**重要**：这些档位不是评分，不显示为 0–100 分；只在报告里以句子出现。系统内部可以计算置信度，但界面上不出现"数学能力 72 分"这类东西。

### 6.3 思想徽章（由证据规则授予）

| 徽章 | 授予条件（全部来自证据，可重算） |
|---|---|
| 观察者 | 首次进入任何关卡时，先产生 ≥2 个观察事件再提交（跨 3 关） |
| 模式识别者 | 2 个结构关拿到迁移印章（换表征通过） |
| 规则设计者 | 1 个规则关的程序在 ≥4 个变体上通过，且至少一次失败后修订 |
| 构造者 | 3 个构造关通过，其中至少 1 次多解变体或不可能证书 |
| 模型构建者 | 2 个模拟关完成"运行→指标不足→调参→达标"的完整链路 |
| 实验者 | 2 个实验关采集 ≥ 规定样本量，且结论不越界 |
| 边界探索者 | 1 个有效反例 + 1 份被接受的不可能性/边界证书 |
| 修正者 | 5 次"失败→修改→通过"的修订链（跨关） |
| 迁移者 | 5 个变体（至少 2 个换表征）通过 |

徽章只在"工坊墙"与报告里出现，不弹全屏庆祝，不发奖励货币；一次授予可回看证据。

### 6.4 思维日志

每次通关或中途退出时，生成一条**可读的回放**：

~~~text
3 月 14 日 · 铺砌挑战
你先试了 3 块"L 形"，发现右下角总留一格（结构缺口）。
第 3 次你把一块换成"长条"，缺口补上了。
换到旋转目标后，你又找到了第二种摆法。
你的判断：先看角上的格子，再决定用哪块。
~~~

日志由事件模板生成，玩家可以补一句自己的话（≤80 字，本地保存，不进任何统计）。玩家可删除单条日志；删除不影响徽章（徽章由证据重算，证据本身可清理，见隐私）。

### 6.5 家长/教师报告

**入口**：档案柜里长按"成人查看"3 秒；不放在孩子主路径上。

**内容**（一屏可读完，可打印 A4）：

1. 本周用了哪几件工具、各用了几次；
2. 在哪些关卡出现了"从试错到结构化"的转变（附一句证据描述）；
3. 四维画像的三档描述（不是分数）；
4. 下一步建议 2–3 条（基于证据缺口，例如"还没有做过反例类挑战，可以试试'最少枚数支付'"）；
5. 本周在工坊的时间（中性陈述，不设目标）；
6. 隐私说明：数据只在本机，无账号、无上传、无广告、无内购。

**不出现**：正确率、做题量、排名、用时排名、"你家孩子落后/超前"。

**导出**：
- 打印/另存 PDF（浏览器打印，A4 样式）；
- 证据包 `.mmfpack.json`（脱敏，无昵称以外的个人信息；教师可导入查看）；v1.1 起支持教师包。

### 6.6 本机档案与隐私

- 默认单档案；schema 从第一天就按 `profileId` 分键，避免以后迁移（`mmf.save.<profileId>` + `mmf.profiles` 索引）。
- 昵称可选，最多 12 字；不询问真实姓名、学校、生日、邮箱。
- 所有数据在 IndexedDB；无网络请求；导出由用户主动触发。
- "清除本机数据"需要长按 3 秒；清除后不可恢复（会提示）。
- 家长/教师可以导出后删除孩子档案；不提供云同步，避免未成年人数据上云。

## 7. 玩家关卡编辑器（v1.1）

**定位**：设计一关是最高阶的理解检测。编辑器不是"地图涂鸦"，而是**复用模板 + 约束 + 变体 + 反馈**的关卡装配台。

**能编辑什么**：
- 选模板（六选一）与学段/主线标签；
- 情境参数（尺寸、符号/形状集合、地图、初始状态）；
- 工具开放（哪些工具、哪些参数范围）；
- 约束与通关条件（模板允许的约束组合）；
- 反馈文案（每个失败类一句，提供默认模板）；
- 变体（至少 1 个迁移变体）；
- 黄金解（自己走一遍，系统记录）与负例（至少 1 个）。

**不能编辑什么**：不能写代码、不能上传脚本、不能引用外部 URL、不能改引擎判定逻辑。

**可解性校验**（发布前必须通过）：
1. zod schema + 模板约束；
2. 求解器找到至少 1 条解（或不可能关的证书检查通过）；
3. 反刷题审计的自动项 + A5/A10 人工复核（无工具提交失败、至少 1 个变体、失败类反馈齐全、无纯选择题）；
4. 试玩：作者自己完成一次，系统确认证据事件链路完整；
5. 导入/导出 JSON 有大小上限与文本白名单；导入后重新跑全部校验。

**发布与分享**：只到**本机关卡库**；通过"导出关卡文件"给同伴/老师，导入时二次校验。没有在线社区、没有服务器、没有排行榜。

**精选关卡**：官方可以随版本内置"玩家精选"（由团队人工审核后随包发布），但不在运行时联网拉取。

## 8. 内容标准（每关必须有的七件东西）

1. **认知目标**：一句话说清这一关训练哪种思维操作（不是知识点名称）；
2. **工具产物**：必须使用哪些工具、产出什么 artifact；
3. **约束/多解空间**：硬约束是什么、允许哪些不同解、简洁线怎么定；
4. **可观察后果**：运行后玩家能看见什么（断在哪、哪个指标变、哪个前提失效）；
5. **失败类 + 反馈**：至少 3 个结构失败类，每个有文案、提示、焦点；
6. **证据计划**：观察/假设/构造/运行/修正/迁移/论证中至少 2 个检查点；
7. **变体**：至少 2 个，必须改变结构/表征/约束之一，禁止只改数字。

### 8.1 反刷题审计 A1–A10（自动项 + 人工项）

| 编号 | 检查 | 自动化 |
|---|---|---|
| A1 | `requiredToolArtifacts` 非空，且 `submit` 无产物必失败 | 是（运行时 + 审计脚本） |
| A1b | 产物被删除/置空/篡改成合法但错误的版本时，必须失败且失败类不是 missing-evidence | 是（差分审计，见 02 文档 14.4） |
| A2 | 动作空间至少包含一种非选择动作（构造/编辑/参数/采集/反例） | 是（模板元数据 + 审计） |
| A3 | 至少 2 条不同形式的有效解；不可能关至少有 1 份可检验证书 | 是（黄金解/求解器） |
| A4 | 每个可达失败类有反馈文案；至少 3 个可达失败类有能触发它的负例 | 是（schema + 负例 fixture） |
| A5 | 删掉情境后仍是一个操作性问题（`constraints`/`toolSpace` 非空，`options` 不能是通关唯一依赖） | 人工复核（第二人签 `manual-audit.md`） |
| A6 | ≥2 个变体，且变体轴不是数字大小 | 是（`variant.axis` 枚举） |
| A7 | 无计时/扣命/排行/分数；文案无伤害性词 | 是（文案词表 + UI lint） |
| A8 | 证据计划 ≥2 阶段，完成时写入证据日志 | 是（运行时断言） |
| A9 | 徽章由证据规则授予，不由通关次数授予 | 是（徽章规则单测） |
| A10 | 每关有认知目标、工具目标与"下一步建议"映射 | 是（schema）+ 人工 |

审计不是"上线前跑一次"，而是 `pnpm audit:levels` 接进 `verify`，每次提 PR 都跑。**A1/A1b/A2–A4/A6–A9 是自动项；A5/A10 由第二人按 `manual-audit.md` 复核，随 PR 归档，脚本只检查清单存在。**

### 8.2 文案规范

- 对 5–8 岁：句子 ≤ 14 字，先动词，配语音；屏幕字少，图与动作优先。
- 对 9–12 岁：可以出现"规则/条件/重复/约束"等词，但每个词第一次出现时用一句人话解释。
- 对 13–18 岁：可以用"不变量/反例/区间/启发式"，但避免学术黑话堆砌；论证板提供句式。
- 禁止词表：失败、惩罚、笨蛋、输了、淘汰、粗心、扣分、排名、倒数、必须、聪明/笨。
- 英文：拉丁字体优先，避免弯引号全角；英文文案单独补丁，构建期检查零中文残留。

## 9. 可访问性与交互基线

- 所有可点区域 ≥ 44×44 CSS px（Phaser 内 ≥ 88 逻辑像素），不依赖 hover；
- ToolDock 全部可键盘操作：Tab 顺序、方向键调滑杆、空格运行、Esc 关闭浮层；
- 颜色不是唯一信息通道：形状/纹理/文字标签同时存在；
- 尊重 `prefers-reduced-motion`：减少镜头运动、禁用大幅弹跳；
- 字号跟随系统（外壳用 rem；画布内文字有最小字号）；
- 屏幕阅读器：外壳与 ToolDock 使用语义化 HTML + ARIA；画布提供"状态摘要"（同一份运行时快照的文本版）；
- 声音总开关；语音可关；所有关键文案同时上屏；
- 平板横竖屏都可玩：手机竖屏上下布局，平板/桌面左右布局；
- 20 分钟休息提醒（一天一次，可关），不强制中断。

## 10. 双语与本地化

| 层 | 中文 | 英文 | 加载 |
|---|---|---|---|
| 界面文案 | `messages.ts` 常驻 | `en.ts` 独立 chunk | `ensureMessages('en')` |
| 关卡摘要 | `levels/<id>.json` | `i18n/en/summaries.ts` | 切语言时加载 |
| 关卡详情 | `details/<id>.level.json` | `i18n/en/<id>.level.json` | 进关时懒加载 |
| 语音 | Web Speech / 原生 TTS `zh-CN` | `en-US` | `AudioBus.speak` |

- 语言只影响三层，游戏逻辑与存档不知道语言的存在；
- 切换语言前先 `await` 文案与内容补丁，避免"界面英文、关卡中文"的半截状态；
- 英文缺失是构建期错误：`content:check` 合并补丁后重新过 schema，且英文 `levelScript` 零中文；
- `<html lang>` 与 `document.title` 跟随；选择存 `localStorage`。

**范围决定**：MVP 只做中文关卡内容 + 双语外壳；v0.9 起补英文关卡内容，v1.0 要求 20 关英文齐全。若确认不做英文内容，内容工作量减少约 30–40%，但英文名/副标题仍保留。

## 11. 明确不做

- 账号、云存档、跨设备同步、排行榜、多人对战；
- 广告、内购、抽卡、体力、连续天数惩罚；
- 计时赛、正确率、分数、星级；
- 在线关卡社区、服务器端内容审核；
- 用 LLM 实时生成题目/提示（离线、可复现、可审计优先）；
- 3D 引擎（铺砌用等距投影表现"三维目标"，不引入 3D）；
- 采集真实姓名、学校、位置、照片、声音。
