# 《数思工坊》技术架构与数据契约

> 本文是工程实施的唯一口径：包怎么分、契约长什么样、运行时如何流转、内容如何校验、数据如何保存、测试与发布如何卡门。技术栈以 **BambooBuddy** 为基线（版本已核对），但玩法与运行时按"思维工具"重新设计。

## 2. 架构原则（不可违背）

1. **逻辑与渲染分离**：`packages/toolkit`、`packages/evidence`、`packages/progress`、所有 `*.logic.ts` 不 import Phaser / Vue / DOM。判定、求解、证据聚合都能在 Node 里跑。
2. **动作驱动运行时**：所有交互（点、拖、调滑杆、采样、提交）都变成 `LevelAction`，由纯 `LevelRuntime` 处理；画布与工具台只是两个视图。自动通关与真实操作走同一条 `dispatch` 路径，不允许另写"自动通关分支"。
3. **平台出口唯一**：存储、音频、语音、文件、生命周期一律经 `PlatformServices`；游戏/工具代码里出现 `localStorage` / `fetch` / `indexedDB` 视为 bug（lint 拦截）。
4. **内容分两半**：摘要（星图/卡片）静态加载；关卡详情（脚本/解/反馈）按关懒加载；英文补丁再懒一层。
5. **确定性**：随机数注入种子，时钟注入 `now()`；纯逻辑层禁止 `Math.random` / `Date.now`。证据、报告、自动通关必须可复现。
6. **数据完备的模板**：模板的判定/求解只依赖 `levelScript`，不为单关写分支；玩家编辑器才能复用同一套引擎。
7. **双视图**：Canvas 负责空间与时间，ToolDock 负责结构化编辑与数据。工具产物是唯一事实，两个视图都读同一份 `RunSnapshot`。
8. **零后端、零联网**：构建产物与运行时都不发网络请求；导入/导出只走用户主动触发的本地文件。
9. **可审计**：每个关卡都有黄金解、负例、变体与失败类；反刷题审计是 CI 门禁，不是人工承诺。
10. **儿童/青少年安全默认值**：不采集个人信息、不设排行榜、不设内购、不做社交；成人报告有门。

**为什么把 `toolkit` 与 `toolkit-ui` 拆开**：六件工具的判定与求解必须能在 Node 里被审计（`audit:levels`），而它们的界面是 Vue；混在一起会把 Vue/DOM 拖进纯逻辑测试与审计 CLI。同理，`templates` 的 `*.logic.ts` 可以 import `toolkit`，但不能 import `canvas-kit`。

### 4.2 关卡清单与上下文

~~~ts
export interface LevelManifest {
  id: LevelId;
  band: Band;
  thread: ThreadId;
  template: TemplateId;
  /** 画布设计尺寸；无画布关卡可为 0×0，由 ToolDock 独占 */
  designSize: { width: number; height: number };
  estimatedMinutes: number;
  hasCanvas: boolean;
  // 工具清单不在这里：工具台按内容的 LevelDetail.tools 渲染，避免 manifest 与内容双份事实
}

export interface LevelContext {
  container: HTMLElement;
  /** 有画布时由宿主创建；无画布时为 null */
  canvasHost: HTMLElement | null;
  manifest: LevelManifest;
  /** 已加载并合并语言的关卡详情 */
  detail: LevelDetail;
  services: PlatformServices;
  locale: Locale;
  reducedMotion: boolean;
  completedBefore: boolean;
  debug?: DebugOptions;
  emit<K extends keyof LevelEventMap>(type: K, payload: LevelEventMap[K]): void;
  requestExit(reason?: 'quit' | 'replay'): void;
}

export interface LevelModule {
  manifest: LevelManifest;
  /** 纯运行时：不碰 DOM；外壳与审计都用它 */
  createRuntime(detail: LevelDetail, opts: RuntimeOptions): LevelRuntime;
  /** 挂载画布（如有）并接上同一个 runtime；无画布关卡实现为空 */
  mount(ctx: LevelContext, runtime: LevelRuntime): Promise<void>;
  unmount(): Promise<void>;
  pause(): void;
  resume(): void;
}
~~~

**关键点**：`createRuntime` 在外壳渲染工具台之前调用；工具台按 `LevelDetail.tools`（顶层）渲染，不依赖关卡模块导出 UI；`mount` 只负责画布。这样无画布关卡（例如纯数据实验）加载的 chunk 里可以完全没有 Phaser。

### 4.4 动作类型

动作是唯一写入运行时状态的入口。类型集中定义在 `packages/game-kit/src/runtime.ts` 的 `ActionPayloadMap`（本文这段是它的镜像，改契约必须两处同步）；模板与工具只做"动作 → 纯逻辑"的映射。

> 纪律：**先加类型、再加处理分支、最后才让 UI 派发**。动作表里没有的类型不能出现在内容或组件里——那会绕过类型检查，autoplay 与真实操作就不再是同一条路径。下面这份清单与实现一一对应，未实现的动作不再预先列出（早期文档列过 `construct/rotate`、`rule/setParam` 等，落地时没有使用，已删除以免误导）。

~~~ts
/** 模式变换：reflect = 镜像展开（对称补墙用） */
export type PatternTransform = 'none' | 'mirror' | 'rotate' | 'shift' | 'reflect';

export interface ActionPayloadMap {
  // 模式卡
  'pattern/inspect': { index: number };
  'pattern/setCycle': { cycle: string[]; transform: PatternTransform };
  'pattern/preview': Record<string, never>;
  'pattern/commit': Record<string, never>;

  // 规则卡
  'rule/place': { block: ProgramBlock; at: number };
  'rule/remove': { id: string };
  'rule/move': { id: string; at: number };
  'rule/run': Record<string, never>;
  'rule/commit': Record<string, never>;

  // 构造块（七种模式共用 place/remove）
  'construct/place': { piece: PiecePlacementInput };
  'construct/remove': { pieceId: string };

  // 参数旋钮
  'knob/set': { key: string; value: number };
  'knob/run': Record<string, never>;
  'knob/compare': { runId: string };
  'knob/reset': Record<string, never>;
  'knob/commit': Record<string, never>;

  // 数据采集器
  'probe/sample': { n?: number };
  'probe/clear': Record<string, never>;
  'probe/focus': { id: string };
  'probe/claim': { claim: ClaimInput };
  /** K 数据关：玩家手动记录的统计条（不是采样结果） */
  'probe/tally': { counts: Record<string, number> };

  // 反例探测器
  'counter/edit': { patch: CounterPatch };
  'counter/test': Record<string, never>;
  'counter/annotate': { premiseId: string };
  'counter/commit': Record<string, never>;

  // 论证板（argue 模板的结构化证书）
  'argue/setClaim': { claim: string };
  'argue/setWarrant': { warrant: string };
  'argue/attachEvidence': Record<string, never>;
  'argue/setScope': { scope: string };
  'argue/commit': Record<string, never>;

  // 宿主统一动作：所有模板都必须处理
  'run': Record<string, never>;
  'submit': Record<string, never>;
  'reset': Record<string, never>;
}

export type LevelAction = {
  [K in keyof ActionPayloadMap]: { type: K; payload: ActionPayloadMap[K] };
}[keyof ActionPayloadMap];

export interface ProgramBlock {
  id: string;
  op: 'forward' | 'left' | 'right' | 'collect' | 'repeat' | 'if-wall';
  n?: number;
  children?: ProgramBlock[];
}

export interface PiecePlacementInput {
  id: string;
  shape: string;
  x: number;
  y: number;
  rot?: 0 | 90 | 180 | 270;
  flip?: boolean;
}

/** 构造工具的产物不一定都是 placement-set：K 数据关的 construct 提交的是 tally。 */
export interface TallyArtifact {
  counts: Record<string, number>;
  order?: string[];
}

/**
 * 结论不是自由文本：三类可校验的结论。
 * - count-compare：K/G1–3 的"最多/最少"（支持并列）
 * - stat：均值/比例 + 样本量 + 可选区间
 * - difference：两组差 + 区间
 */
export type ClaimInput =
  | { kind: 'count-compare'; category: string; direction: 'most' | 'least'; tiedWith?: string[]; n: number }
  | { kind: 'stat'; statistic: 'mean' | 'proportion'; value: number; n: number; ci?: [number, number] }
  | { kind: 'difference'; delta: number; ci: [number, number]; n: number };
~~~

`ProgramBlock` / `PiecePlacementInput` / `TallyArtifact` / `ClaimInput` / `CounterPatch` 也在 `game-kit` 中定义为 JSON 可序列化结构；它们是纯数据，可存进内容 JSON、证据摘要与编辑器草稿。

### 4.6 工具规格（声明式）

工具台不写死六个组件，而是按内容声明的 `ToolSpec` 渲染：

~~~ts
export type ToolSpec = ToolSpecBase & (
  | { kind: 'pattern'; config: PatternToolConfig }
  | { kind: 'rule'; config: RuleToolConfig }
  | { kind: 'construct'; config: ConstructToolConfig }
  | { kind: 'knob'; config: KnobToolConfig }
  | { kind: 'probe'; config: ProbeToolConfig }
  | { kind: 'counter'; config: CounterToolConfig }
);

export interface ToolSpecBase {
  /** 工具在工具台上的标题/说明的 i18n key；内容不写长文案 */
  titleKey: string;
  descriptionKey: string;
  /** 工具门：哪些产物算"用过这件工具" */
  requiredArtifacts: string[];
}
~~~

每个 `*ToolConfig` 都是 JSON 可序列化参数（范围、选项、初始值、显示单位）。内容 JSON 里的 `tools` 直接对应这个结构；zod 校验在 `templates/<template>/schema.ts` 与 `toolkit` 的 `toolConfigSchemas` 双层完成。

`solutions` 至少 2 条（不可能关例外：至少 1 份证书 + 0 条常规解，见审计 A3）；`negativeSamples` 至少 3 条，覆盖至少 3 个失败类；`variants` 至少 2 条。这些不是"建议"，是 `content:check` 的硬错误。

## 5. 运行时数据流

~~~text
                 ┌──────────────────────────────┐
                 │ apps/site WorkshopView       │
                 │  · 加载 LevelDetail（懒）     │
                 │  · createRuntime()           │
                 │  · 渲染 ToolDock（Vue）       │
                 │  · 挂载 Canvas（Phaser，可选） │
                 └───────┬──────────────┬───────┘
                         │ dispatch     │ subscribe(snapshot)
                         ▼              ▲
                 ┌──────────────────────────────┐
                 │ LevelRuntime（纯 TS 状态机）   │
                 │  · 工具状态/产物/检查点        │
                 │  · run → Verdict              │
                 │  · submit → 三道门             │
                 └───────┬──────────────┬───────┘
                         │ EvidenceDraft│ Verdict
                         ▼              ▼
                 ┌──────────────┐  ┌────────────────┐
                 │ evidence     │  │ 完成面板/反馈    │
                 │ 聚合/徽章/报告 │  │ 失败类→文案     │
                 └──────┬───────┘  └────────────────┘
                        ▼
                 ┌──────────────────────────────┐
                 │ ProgressManager → SaveData    │
                 │ IndexedDB（按 profileId 分键） │
                 └──────────────────────────────┘
~~~

**纪律**：

- 画布与工具台都不直接改状态；只能 `dispatch`。
- 画布与工具台都不写存档；完成/失败/证据由外壳统一落盘。
- 运行时不知道 `profileId`、语言、路由；这些由外壳注入。
- `autoplay` 是运行时的方法，内部逐条 `dispatch` 内容里的黄金解；审计与 e2e 共用。

## 6. 模板实现规范

每个模板继承同一套骨架，按需增删文件：

~~~text
packages/templates/src/<template>/
├─ schema.ts      # zod：levelScript、variant patch、artifact、feedback keys
├─ logic.ts       # 纯函数：validateArtifact / actionsFor / applyVariant / failure classes
├─ runtime.ts     # createXxxRuntime：把 RuntimeAdapter 交给 shared/runtime 组合成 LevelRuntime
├─ scene.ts       # Phaser：只画 + 发动作 + 读 snapshot（该模板/关卡无画布时没有此文件）
├─ layout.ts      # 纯常量：画布坐标、格宽、按钮位置（e2e 可 import，不含 Phaser）
└─ index.ts       # createXxxScene / buildXxxTools / createXxxRuntime 的出口
~~~

### 6.1 模板必须实现的纯函数

**实现口径是 `RuntimeAdapter`，不是早期设想的 `TemplateLogic`。** 早期文档写的是
`init / reduce / solve` 这一套；落地时发现六个模板的"状态"形态差异太大（程序 AST、盘面、
指标表、证书），统一 reduce 只会造出一堆 `switch (template)`。现在的做法是：
每个模板自己管状态，只把**共享运行时需要的那几件事**以适配器形式交出来，
`shared/runtime.ts` 负责 submit/run/reset/autoplay、证据草稿、快照与订阅。

~~~ts
export interface RuntimeAdapter<S> {
  /** 从详情与时钟构造初始状态（工具态）；不碰 DOM */
  initialState(detail: LevelDetail, now: number): S;
  /** 只处理工具动作；run/submit/reset 由共享运行时统一处理 */
  apply(state: S, action: LevelAction): AdapterResult<S>;
  /** 当前可提交的产物；没有产物时返回 null（提交会被拒） */
  artifact(state: S): unknown | null;
  /** 产物摘要（给快照/证据/完成面板） */
  artifactSummaries(state: S): ArtifactSummary[];
  /** 证据检查点是否满足 */
  checkpoints(state: S, ctx: TemplateCheckpointContext): Record<string, boolean>;
  /** 工具编辑态（ToolDock 回显用） */
  toolState(state: S): Partial<ToolStateMap>;
  /** 用最终产物直接校验（审计/多解/编辑器用，不依赖动作回放） */
  validate(detail: LevelDetail, variant: RuntimeVariant, artifact: unknown): Verdict;
  /** 黄金解 → 动作序列（autoplay 用；必须走与玩家相同的 dispatch 路径） */
  actionsFor(detail: LevelDetail, variant: RuntimeVariant, artifact: unknown): LevelAction[];
  /** 迁移门：变体列表与失败类（可选；多数模板用 templates/verifiers.ts 的注册表） */
  transferVariants?(detail: LevelDetail): RuntimeVariant[];
  transferFailureClass?(detail: LevelDetail): string;
  /** argue 模板的结构化证书状态（可选） */
  argumentState?(state: S): ArgumentSnapshot | undefined;
}
~~~

**为什么同时要 `validate` 与 `actionsFor`**：审计要快速验证"这个产物是否满足约束/是否多解"，不需要回放整段动画；autoplay 要真实走一遍动作链，保证 e2e 测的是玩家路径。两者共享同一套约束检查函数，避免判定漂移——这条纪律没变，只是接口名从 `validateArtifact` 换成了 adapter 上的 `validate`（审计脚本经 `templates/verifiers.ts` 用到同一个实现）。

**没有 `solve`**：编辑器（v1.1）才需要可解性求解器；当前审计靠"内容自带的黄金解 + 负例 + 变体验证"，不跑搜索。补 `solve` 时不要把搜索放进运行时，它应该和 `verifiers.ts` 一样是纯函数入口。

**已知休眠缺陷（记录在案，未修）**：`construct/verifier`、`experiment/verifier`、`simulate/verifier` 的部分模式在
`validateArtifact` 里没有把 variant 应用到 script，只校验 base；目前这些模式的 transferVariants 为空、
移动变体走不到这条路径，所以是休眠缺陷。等这些模式接入迁移门之前必须先修它，否则变体审计会假绿。

### 6.2 模板清单

| 模板 | 纯逻辑要点 | 画布要点 | 判定/审计要点 |
|---|---|---|---|
| `pattern` | 周期推断、补全、换表征与镜像展开迁移 | 序列带、积木/瓷砖、裂纹动画 | 逐格比对规则；缺口与规则一致性；变体换表征 |
| `rule` | 程序 AST、执行器、步数上限、变体泛化 | 网格地图、角色、障碍、收集物 | 回放步进；墙/循环/漏星/未达终点；旋转迁移门 |
| `construct` | 约束检查（覆盖/重叠/对称/连通/预算/分配/课表/边界），等距投影 | 网格/等距板、块盘、旋转翻转 | 约束满足 + 反例探测器（贪心失效）；不可能证书 |
| `simulate` | 确定性排队/路线模拟、指标、预算 | 简化城镇、车辆/队伍、时间轴 | 双种子复算；覆盖/等待/成本/加班；参数合法域 |
| `experiment` | 种子对局、胜率/区间、抽样与推断 | 可选轻量对局动画或纯图表 | 样本量、区间覆盖、结论与数据一致；两批抽样 |
| `argue` | 主张/依据/证据/边界证书、反例检查、不变量检查 | 结构/图表/成本曲线 | 证书检查器（选项来自 levelScript）+ 铺设构造 |

### 6.3 失败类与反馈的绑定

- 模板的 `FAILURE_CLASSES` 是权威清单；
- 内容 `feedback` 必须覆盖"该关实际可触发"的类；`content:check` 用模板的 `reachableFailureClasses(script)` 计算必须覆盖的集合；
- 每个失败类在 `feedback` 里有 `messageKey/hintKey/focus`；文案在 `i18n` 与内容补丁里；
- 负例 `negativeSamples` 必须能触发对应类；`audit:levels` 校验。

### 6.4 无画布模板

`experiment` 与 `argue` 的正文可以按关卡选择由 Vue 面板 + SVG 图表承担，不为画布 import `canvas-kit`。这样这些关卡的 chunk 不含 Phaser，冷进入更快，也让"数据工作台"可以被键盘与屏幕阅读器完整操作。模板本身不强制有无画布，由 `levelScript` 的 `scenario.kind` 与关卡入口决定。

### 7.2 摘要与详情

~~~text
packages/content/src/
~~~

**双语是"内联字段"而不是"英文补丁文件"**：早期方案（本文旧版）计划用 `i18n/en/<id>.level.json`
单独切 chunk；落地时改成在每份详情里直接放 `titleEn / thinkingTargetEn / introEn / promptEn /

### 7.3 `loadLevel()`

~~~ts
// 只对已发布关卡建 loader；Record 少一条 typecheck 就报
const LOADERS: Record<ShippedLevelId, () => Promise<unknown>> = {
  'k-structure-pattern-path': () => import('./details/k-structure-pattern-path.level.json'),
  // …20 条，与 SHIPPED_LEVEL_IDS 一一对应
};

export async function loadLevel(
  id: ShippedLevelId,
  _locale: Locale = 'zh-CN',        // 详情里同时有中英字段，locale 由调用方交给 localize.ts
): Promise<LevelDetail | null> {
  const summary = getLevelSummary(id);
  if (!summary) return null;                    // 未发布/旧链接：调用方回星图，不白屏
  const loader = LOADERS[id];
  if (!loader) return null;
  const raw = await loader();
  const detail = (raw && typeof raw === 'object' && 'default' in raw ? raw.default : raw) as LevelDetail;
  if (detail.id !== id) throw new Error('关卡详情 id 不一致：' + id);  // 构建期已由 content:check 保证
  return detail;
}
~~~

- Vite 会为每个 `details/*.level.json` 切一个 chunk，文件名由 `apps/site/vite.config.ts` 的 `chunkFileNames` 命名为 `content-<id>-<hash>.js`；
- 中文与英文在同一份详情里，因此"切语言"不需要再发请求；`ForgeView` / `WorkshopView` 用 `localizedSummary` / `localizedDetail` 取当前语言字段，缺失回退中文；
- 运行时 id 自检只防"构建配置错位"；真正的形状校验在 `content:check`（构建期 zod + 语义检查）。

### 7.4 内容体检（`content:check`）

除了 zod 形状检查，必须做语义检查：

| 检查 | 失败示例 |
|---|---|
| id 与文件名/枚举一致 | 文件名 `k-pattern` 但 JSON 里是 `k-structure-pattern-path` |
| 20 个 `LEVEL_IDS` 全覆盖，无重复 | 少一关 / 两关同 id（默认只对 `SHIPPED_LEVEL_IDS` 报错；`--require-all` 时 20 个都必须有内容） |
| 摘要与详情字段一致 | 摘要模板是 `construct`，详情脚本按 `rule` 写 |
| 每个模板的 `levelScript` 能过 `parseScript` | 网格越界、块 id 重复、参数超范围 |
| 工具声明与模板兼容 | `pattern` 关卡声明了 `probe` 但脚本没有数据源 |
| 反馈覆盖可达失败类 | 负例能触发 `construct-gap`，但 `feedback` 没有这一条 |
| 解与负例可校验 | 黄金解不通过；负例没触发声明的失败类 |
| 变体轴合法且 ≥2 | `axis: 'number-size'`；只有一个变体 |
| 难度四轴在 1–5 | 出现 0 或 9 |
| 文案禁词 | "失败了""你太粗心" |
| 英文零中文残留 | 英文标题与中文相同；`levelScript` 里还有中文字符串 |
| 徽章引用存在 | 引用了未注册的 `BadgeId` |

content:check 的输出按关卡分组，失败直接非 0。

### 7.5 参数化变体

变体不是"同一关换数字"，而是：

| 轴 | 允许的变化 | 例子 |
|---|---|---|
| `structure` | 结构/拓扑/层级 | 路径从直线变成带回环；地图从 5×5 变 7×7 但保持同类 |
| `representation` | 表征 | 颜色序列 → 形状序列；表格 → 图；坐标 → 方向指令 |
| `constraint` | 约束组合 | 覆盖 → 覆盖 + 对称；预算从宽松到冲突 |
| `transfer` | 规则族/领域 | 从"最少枚数"迁移到"最少步数"；从"排队"迁移到"库存" |

模板提供 `applyVariant(script, patch)`；补丁必须是**结构化覆盖**而不是字符串替换。`content:check` 拒绝 `axis` 为 `number-size`，并要求每个变体都能被 `solve` 或 `validateArtifact` 处理（不可能变体需要证书）。

## 8. 存档、档案与证据

### 8.1 存储键与档案


~~~ts
  lastArtifact?: { kind: string; summary: string };
}

  id: string;
  at: number;
  levelId: LevelId;
  variantId: string;
  stamps: StampId[];
  toolIds: ToolId[];
  failureClasses: string[];
~~~

### 8.3 存档迁移与健壮性

沿用 BambooBuddy 的纪律：

- `MIGRATIONS` 是"旧版本 → 下一版本"的函数链；每一步只补字段/换算，不清空；
- 每个字段有 sanitize：坏字段只丢它自己，不连累整份存档；
- 只有"来自未来版本"（`schemaVersion > CURRENT`）才整体回空档；
- 读档 single-flight；写盘失败只置 `unsaved`，不打断当前关卡反馈；
- 证据独立存储（见 8.4）：裁剪时把计数并入 `EvidenceAggregate`，徽章与报告可以"重算历史"，不会因为清理日志而倒退。

### 8.4 证据聚合与报告

~~~ts
export interface EvidenceProfile {
  version: 1;
  dimensions: {
    structure: DimensionSignal[];
    rule: DimensionSignal[];
    model: DimensionSignal[];
    boundary: DimensionSignal[];
  };
  /** 报告用的"下一步建议"（确定性规则，不是 LLM） */
  recommendations: Recommendation[];
}

export interface DimensionSignal {
  id: string;                   // 'observed-before-first-submit'
  value: number;                // 计数/比例
  sample: number;               // 分母
  band: 0 | 1 | 2 | 3;          // 报告三档（0 = 证据不足）
  evidenceRefs: string[];       // 事件 id / 关卡 id
}
~~~

- 证据存储是 append-only：`EvidenceStore.append(events)` 只追加；`recent(limit)` 按时间倒序读取；`clear()` 只在清档时调用；
- 聚合是纯函数：`aggregate(events, agg, levels, now) → EvidenceProfile`；
- 徽章规则是纯函数：`awardBadges(profile, levels) → BadgeId[]`；已授予的记录在存档里，重复计算不会重复弹；
- 报告是纯函数：`buildReport(profile, locale, now) → ReportModel`；外壳只渲染；
- 报告文案来自 i18n + 证据参数，不做自由文本猜测；
- 证据包导出：`ReportPack { version, generatedAt, profileNickname?, levelSummaries, dimensions, recommendations }`，不含原始事件（更隐私），教师导入后只读展示。

```ts
export interface EvidenceRecord {
  version: 1;
  events: EvidenceEvent[];       // 最近 3000 条，按时间升序
}

export interface EvidenceStore {
  append(events: EvidenceEvent[]): Promise<void>;
  recent(limit: number): Promise<EvidenceEvent[]>;
  loadAggregate(): Promise<EvidenceAggregate>;
  saveAggregate(agg: EvidenceAggregate): Promise<void>;
  clear(): Promise<void>;
}
```

**裁剪策略**：

- `append` 后若超过 3000 条，删掉最旧的并把计数并入 `EvidenceAggregate`（总数、按关卡/工具/失败类/阶段的计数）；
- 单条事件序列化 ≤ 1.5 KB；`metrics` 最多 8 个数值键；
- 报告与画像只用 `EvidenceAggregate` + 最近事件；不依赖完整历史；
- 一次完成关卡通常只追加 5–30 条事件，不触发整袋重写；清档时 `clear()` 同时清 `evidence` 与 `evagg`；
- 运行时的 `onEvidence` 只产生 `EvidenceDraft`（不含 id/profileId/at）；外壳补齐后写入 `EvidenceStore`。M0 的实现是"每条草稿立即追加"（先保证链路正确、事件不丢），M1 起按 2 秒或阶段结束批量 `append`，减少写盘次数；
- 失败/退出时也必须 flush，否则"失败→修正"链路会缺前半段证据。

### 8.5 ProgressManager

下面是**实现**的公开面（早期文档里的 `recordJournal` / `recommend` / `exportReport` /
`clearAll` / `CompletionOutcome` 从未落地，已删；推荐与报告是 `@mmf/evidence` 的纯函数，
由外壳直接调用，不经过 ProgressManager）：

~~~ts
export class ProgressManager {
  constructor(store: ProgressStore, evidence: EvidenceStore, clock: () => number, now?: number);
  /** 读档 + 迁移；并发调用只加载一次（single-flight） */
  init(): Promise<SaveData>;
  /** 深拷贝快照：调用方改它不会污染内部状态 */
  snapshot(): SaveData;
  /** 写关卡完成；未知 levelId 直接返回快照（不落盘） */
  completeLevel(input: CompletionInput): Promise<SaveData>;
  /** 证据批次：清洗草稿、单条 ≤1.5 KB、坏草稿整条丢弃且不占 revision */
  recordEvidence(levelId: LevelId, drafts: EvidenceDraft[]): Promise<void>;
  /** 最近证据（最新在前） */
  recentEvidence(limit?: number): Promise<EvidenceEvent[]>;
  /** 按证据重算徽章；幂等，已授予不重复弹 */
  refreshBadges(now?: number): Promise<BadgeId[]>;
  /** 清档：存档 + 证据 + evagg 一起清 */
  clear(): Promise<SaveData>;
}
~~~

- `completeLevel` 只接受"通过"的 `Verdict`；失败不写关卡完成，但失败类进证据；
- 完成时生成 `JournalEntry`（由运行时/外壳构造），更新 `LevelProgress`、`ToolUsage`、`stamps`；
- 写盘走**串行队列**：并发完成时落盘顺序 == 内存更新顺序；写失败只吞错，不打断关卡反馈（§8.3）；
- 徽章在完成/退出时重算，取满裁剪上限（`MAX_EVIDENCE_EVENTS`），引用取**最新**的 20 条事件；
- 推荐（`recommend`）与报告（`buildReport` / `toReportPack`）在 `@mmf/evidence`，ProgressManager 不重复实现。

### 10.3 WorkshopView 生命周期（关键）

~~~ts
async function openLevel(levelId: ShippedLevelId) {
  await ensureSummaries(locale);                            // 先就位语言补丁
  const module = (await registry[levelId]()).default;      // 关卡 chunk（可能含 Phaser）
  const detail = await loadLevel(levelId, locale);          // 详情 chunk
  if (!detail) { navigate('/forge'); return; }              // 未发布/内容缺失：回星图
  const runtime = module.createRuntime(detail, {
    seed: seedFor(levelId, profileId),
    now: platform.now,
    locale,
    reducedMotion,
    onEvidence: (draft) => void progress.recordEvidence(draft),
  });
  const ctx = createLevelContext(module.manifest, detail, host, runtime);
  await module.mount(ctx, runtime);
  // ToolDock 绑定 runtime；完成/失败由 runtime 的 snapshot/verdict 驱动
}
~~~

纪律（与 BambooBuddy 同源，但加上双视图）：

- 挂载前先 `await` 读档（深链直达时，秒通关写入不能被旧快照覆盖）；
- `unmount` 必须 `module.unmount()` + `game.destroy(true)`，并断开 runtime 订阅；否则路由切换残留 canvas 与 rAF；
- 切后台：`module.pause()` + `audio.stopSpeech()`；回前台 `resume()`；
- 画布与工具台共享一个 runtime，不各自维护副本；
- 完成面板只由 `Verdict.passed` 触发；失败横幅只由 `Verdict.failure` 触发；
- 退出时如果有"失败→修改→通过"，生成修正回放日志。

### 10.4 响应式布局

- 手机竖屏：画布区 `min(52vh, 420px)`，工具台在下方可滚动；
- 平板/桌面：左右两栏，画布 `minmax(0, 1fr)`，工具台 `380–460px`，可折叠；
- 无画布关卡：工具台居中，最大宽度 `920px`；
- 工具台字体用 rem，跟随系统字号；画布内最小字号 22 逻辑像素；
- `prefers-reduced-motion` 时禁用镜头缓动与大幅弹跳（runtime 的 `reducedMotion` 与 CSS 双保险）。

## 12. 双语与本地化

| 层 | 事实来源 | 加载 |
|---|---|---|
| 语言清单 | `content/src/ids.ts` 的 `LOCALES / Locale / DEFAULT_LOCALE` | 常量 |
| 界面文案 | `i18n/src/messages.ts`（zh 表）+ `en.ts`（en 表） | 两张表都随 i18n 包进 chunk；`ensureMessages` 目前是空实现的兼容接口 |
| 关卡摘要 | `levels/<id>.json` 里的 `titleEn / thinkingTargetEn` | 与摘要同 chunk，切语言只切字段 |
| 关卡详情 | `details/<id>.level.json` 里的六个 `*En` 字段 | 进关时懒加载同一份详情 |
| 证据/徽章/报告 | `evidence/src/localize.ts` | 按 locale 出英文标签与总结 |
| 语音 | `AudioBus.speak(text, locale)` → `speechLang()` | zh-CN / en-US |

纪律：

1. 游戏/工具不知道语言：外壳把合并后的 `LevelDetail` 交给运行时；文案 key 由运行时产生，外壳渲染；
2. 切换语言是同步的（字段都在内存里），但要先 `await` 存档就位再切，避免"界面英文、卡片中文"的半截状态；
3. 英文漏翻是构建期错误：`content:check` 要求 20 关六个英文字段齐全、零中文残留、无全角标点；
4. `<html lang>` 与 `document.title` 跟随；语言选择经 `PlatformServices.preferences` 存 `localStorage`（封装在 `platform`，外壳不直接写 `localStorage`）；
5. 英文版面：按钮/卡片允许换行；`ToolDock` 宽度自适应；长英文不缩到不可读；
6. **已知缺口**：模板里的失败反馈仍以中文句子直接当 `messageKey`，英文界面会回退中文。`content:check` 对这类 key 记警告，等 i18n 收口后升级为错误（见 §14.4 的 A4 说明）。

~~~ts
  preview: { host: '127.0.0.1', port: 5193, strictPort: true },
  build: {
    target: 'es2022',
    chunkSizeWarningLimit: 1100,
    rolldownOptions: {
      output: {
        codeSplitting: {
          groups: [{ name: 'vendor-phaser', test: /node_modules[\\/]phaser[\\/]|canvas-kit[\\/]vendor[\\/]phaser-trim/ }],
        },
        chunkFileNames(chunk) {
          const id = chunk.facadeModuleId ?? '';
          const level = /[\\/]games[\\/]forge[\\/]src[\\/]levels[\\/]([^\\/]+)\.ts$/.exec(id);
          if (level) return 'assets/level-' + level[1] + '-[hash].js';
          const detail = /[\\/]content[\\/]src[\\/]details[\\/]([^\\/]+)\.level\.json$/.exec(id);
          if (detail) return 'assets/content-' + detail[1] + '-[hash].js';
          if (chunk.name.includes('phaser')) return 'assets/vendor-phaser-[hash].js';
          return 'assets/[name]-[hash].js';
        },
      },
    },
  },
});
~~~

### 13.2 体积预算（M0 建立基线后校准）

| 预算项 | 上限 | 说明 |
|---|---|---|
| 首屏 JS + CSS（gzip） | ≤ 85 KB | 工坊大厅/星图，不含 Phaser |
| 首屏 JS + CSS（原始） | ≤ 260 KB | 桌面/安卓壳本地加载 |
| 单个懒加载 chunk（gzip） | ≤ 280 KB | 最大是 Phaser 裁剪版 |
| 单个懒加载 chunk（原始） | ≤ 1100 KB | 同上 |
| 单关详情 chunk（gzip） | ≤ 40 KB | 内容/解/负例/变体 |
| dist 原始大小 | ≤ 4 MB | 20 关 + 双语 + 全部代码 |
| 单个非代码资源 | ≤ 200 KB | 预期为零 |
| 非代码资源合计 | ≤ 600 KB | 零位图字体，预期为零 |

预算不是越宽松越好：`check-size.mjs` 要区分首屏引用、内联脚本、懒加载 chunk、资源与 dist 总量；任何一项超限就红，改预算必须写原因。BambooBuddy 的实测基线（首屏 54–60 KB、Phaser chunk 220 KB、dist 1.2 MB）只作参考，不当作本项目的成绩。

## 14. 质量门禁

### 14.1 一条命令

~~~text
pnpm verify
 ├─ typecheck      vue-tsc --noEmit（全仓 strict，含 .vue）
 ├─ lint           eslint 10 flat：风格 + 架构边界 + 纯逻辑禁用随机/时钟
 ├─ test           Vitest：工具、模板、证据、存档、内容
 ├─ content:check  内容/模板/双语/失败类/变体/禁词
 ├─ audit:levels   反刷题自动项（A1/A1b/A2–A6/A8）+ autoplay 走通；A5/A10 人工清单
 ├─ pack:check     工程/打包体检（脚本齐全、vendor 就位、首关 manualAudit）——**不检查尚未存在的原生壳**
 ├─ build          Vite 生产构建
 └─ size           体积门禁（必须等 build 结束，串行）
~~~

前 6 步互不依赖，并行跑；`size` 单独串行（BambooBuddy 的教训：并行读 dist 会读到上一轮产物，出现假绿）。

### 14.3 e2e 约定

- 调试桥 `window.__mmf`：`events` 扁平字符串、`snapshot`、`save`、`lastError`；
- 事件命名：`level:start:<id>`、`run:fail:<class>`、`run:pass`、`level:complete:<id>`、`evidence:<phase>`、`journal:add`；
- 每关 autoplay 用 `#/play/<id>?autoplay=1&instant=1`；生产分享链接不生效；
- 真实操作用例目前有 12 条（覆盖模式点选、构造摆放、支付硬币+反例、采样统计、论证板、路网、课表、边界等），全部通过 `data-testid` 定位，坐标类常量在 `packages/templates/src/layout.ts`；**不 import 场景模块**（Playwright 在 Node 里加载 Phaser 会炸）；
- **没有视觉回归基线**：截图只在失败时由 `playwright.config.ts` 的 `screenshot: 'only-on-failure'` 保留，不做像素比对；
- 每个用例失败时保留 trace 与截图；CI 上传 artifact。

### 14.4 反刷题审计（`audit:levels`）

对每个关卡执行：

~~~text
读取详情 → 模板 parseScript
 A1  无工具提交：runtime.dispatch({ type: 'submit', payload: {} }) → passed === false 且 missingEvidence 非空
 A1b 空产物（{}）走 validateArtifact → 必须被结构反馈拒绝，且 missingEvidence 为空（不能当成"缺证据"）
 A2  actionsFor(solution[0]) 至少含 1 个非选择动作；非选择动作少于 2 种时记警告
 A3  至少 2 条有效解，且 2 条的产物 JSON 互不相同
 A4  负例逐个触发声明的失败类；reachableFailureClasses ⊆ feedback keys；≥3 个失败类有负例
 A6  变体 ≥2 且 applyVariant 可解析；transferVariants 逐个用黄金解验证通过
 A8  evidencePlan ≥2 阶段；runtime.autoplay() 真的走到 passed、checkpoints 全满足、产生过证据草稿
 A5/A10 只检查 manualAudit.reviewed 与 ISO 日期，判断留给人
~~~

**A1b 的边界（别把计划当现状）**：

- 当前脚本覆盖"空产物"这一种消费性差分；
- 文档早期设想的"逐个删除 `requiredToolArtifacts`、替换成结构合法但内容错误"没有实现——它需要对每个模板知道"哪个产物可以单独摘掉"，属于内容作者的知识，脚本无法通用。要补的话先改模板暴露产物枚举，再扩展脚本，不要写死某关的键名。

**已知缺口**：A7（无计分/无计时 UI 的静态审计）与 A9（徽章规则单测）目前由 `packages/evidence/src/narrative.test.ts` 的 `evaluateBadges` 用例覆盖；若以后拆出独立 `badges.test.ts`，记得同步本节。

**A5/A10 是人工项**：

- A5（删掉情境后仍是操作性问题）与 A10（认知目标/工具目标/推荐映射）不塞进自动脚本；每关 PR 附带 `manual-audit.md`（检查项 + 复核人 + 日期），由第二人签字；
- `audit:levels` 只检查 `manualAudit` 字段是否存在、是否引用该文件，不替人做判断；
- `pnpm verify` 通过 ≠ A5/A10 已通过；发布检查表单独列人工项。

**A9 在单测里**：徽章规则是 `evidence` 包的纯函数，由 `packages/evidence/src/narrative.test.ts` 的 `evaluateBadges` 用例覆盖（含"空档 9 枚都未获得""存档已授予优先""边界探索者只认 outcome=pass 的反例产物"），不在关卡审计里重复。

任何一条自动项失败，`pnpm verify` 红。审计脚本与运行时共用 `templates/<t>.logic.ts`，不另写判定。

## 16. 安全与隐私

### 16.1 零联网

- 构建产物不含任何 API 地址；无第三方 CDN、无字体外链、无统计脚本；
- e2e 用 `page.route('**', ...)` 监控并断言除本地资源外 0 请求；
- CSP 由**构建期注入**，不写在 `index.html` 里：`apps/site/vite.config.ts` 的 build-only 插件在产物 `</head>` 前插入 `<meta http-equiv="Content-Security-Policy">`，策略与插入逻辑在 `apps/site/src/shell/csp.ts`（有单测）。原因：dev 的 HMR 需要 `ws://` 连接，静态写死 `connect-src 'none'` 会打断热更新；生产产物才收紧到 `connect-src 'none'`。策略：`default-src 'self'; connect-src 'none'; img-src 'self' data:; style-src 'self' 'unsafe-inline'; script-src 'self'; object-src 'none'; base-uri 'self'`；
- 不引入任何会发请求的依赖（不用在线字体、不用远程图标、不用 analytics）。

### 16.2 导入校验

**现状只有"报告证据包只读导入"这一条导入通道**（关卡导入/编辑器属 v1.1）：

- 只接受 JSON，大小上限 512 KB（超过整包拒绝，先于任何解析）；
- 报告包用 `parseReportPack` 收敛：版本必须为 1、`generatedAt` 必须是有限数字、对象字段逐个白名单；
- 文本字段按码点截断，含 HTML/脚本协议（`<...>`、`javascript:`、`data:text/html`）整包拒绝——但纯文本里的 `a < b` 不误杀；
- 导入结果只渲染，不合并进 `SaveData`；渲染层不 v-html；
- v1.1 关卡导入落地时，除同一个 `parseReportPack` 式闸门外，还必须重跑 `parseScript` + `audit:levels` 的自动项。

### 16.3 未成年人数据

- 不询问真实姓名、学校、生日、联系方式、位置；
- 昵称可选且可随时改/清；
- 无账号、无云同步、无社交、无广告、无内购；
- 证据与日志只在本机；导出由用户主动触发，导出包不含原始自由文本；
- 家长/教师可一键清除档案；清档需长按确认；
- 隐私说明放在 `#/about` 与报告页底部，孩子也能读到一句人话。

## 17. 性能

| 场景 | 目标 | 措施 |
|---|---|---|
| 首屏 | 冷启动 ≤ 2 s（中端平板，本地） | 首屏不含 Phaser/zod/关卡详情；路由懒加载 |
| 单关进入 | ≤ 2 s | 关卡 chunk + 详情 chunk 并行；画布初始化后显示骨架 |
| 工具交互 | ≤ 100 ms 反馈 | 纯逻辑同步；图表增量更新；避免深度 reactive |
| 单次判定 | ≤ 200 ms | 判定为纯函数；构造关搜索加剪枝/预算；超预算提示"先试一个小一点的构造" |
| 1000 局模拟 | ≤ 1 s 且不卡交互 | 分片（每帧 50–100 局）+ 进度条；结果缓存；必要时 Worker（v1.1 评估） |
| 证据落盘 | 不阻塞动画 | 批量写、节流；完成时一次写 |
| 长会话 | 内存稳定 | 证据裁剪；runs 只留 10 条；画布对象池/销毁 |

**测量方式（现状）**：

- 体积：`scripts/check-size.mjs`（首屏 / 最大懒加载 chunk / dist 总量），`pnpm verify` 里串行跑；
- 端到端冷进入：e2e 的 `level:start` → `level:ready` 事件可以在调试桥里观察，但**尚未做成断言**；
- **尚未实现**：`bench-levels.mjs`（模板判定/求解 p50/p95）、Playwright `performance.mark` 基准、CI 回归阈值。

上表是**目标值**，不是实测值。补基准时优先做两件事：
1. `scripts/bench-levels.mjs`（纯 Node，不需要浏览器）先给 `validateArtifact` 与 `solve` 出 p50/p95；
2. e2e 里加一条 `level:ready < 2000ms` 的断言，避免"只能说没测到"。

在这些落地前，发布说明不得引用"性能达标"。

| 13 | 高中边界关用"可检验证书"而非自由作文 | 可审计、可反馈、可自动判 | 只覆盖特定不变量/反例族，不追求全形式化证明 |
| 14 | 3D 目标用等距投影 | 保留"三维目标"的思维挑战，不引 3D 引擎 | 视觉不是真 3D |
| 15 | 提示与变体调节代替数值难度 | 符合"沿思维复杂度上升" | 需要证据驱动的推荐逻辑 |

## 19. 踩坑预防（BambooBuddy 实测 + 本项目新增）

1. **zod 4 的 `z.record(enum, number)` 是穷尽记录**：部分字段用 `z.partialRecord`（BambooBuddy 踩过）。
2. **Phaser Graphics 的 `fillEllipse` 只收 4 个参数**：统一走 `canvas-kit/draw.ts` 助手，不直接调底层。
3. **e2e 不能 import 场景模块**：Playwright 在 Node 加载 Phaser 会执行顶层依赖；真实坐标放 `layout.ts`（纯常量）。
4. **外壳入口不能引 zod**：摘要静态加载，运行时校验交给 `content:check`；常量拆 `content/ids`。
5. **Phaser 实例必须 `shallowRef`**，`unmount` 必须 `destroy(true)`，订阅要断开；否则路由切换残留 canvas/rAF。
6. **存档迁移不能"版本不等就清空"**：逐字段 sanitize；只有未来版本才回空档。
7. **拉丁字体排最前**：弯引号在 CJK 字体里全身宽，英文副标题会像多空格。
8. **英文必须独立懒加载**：界面英文表与内容补丁都别静态进主包。
9. **Container 命中区按左上角原点**：传居中矩形会让可点区只剩左上 1/4（BambooBuddy 修复过）。
10. **不要把 runtime 放进 Vue 的深层 reactive**：快照用 `shallowRef`/`markRaw`，订阅按需更新；否则每帧比较整棵对象图。
11. **Monte Carlo 阻塞主线程**：1000 局要分片；每帧 50–100 局，留出绘制与输入时间。
12. **证据日志无限增长**：3000 条上限 + 聚合计数；写盘前裁剪。
13. **画布与工具台抢焦点**：ToolDock 输入框聚焦时暂停画布键盘快捷键；Esc 先关浮层再退出。
14. **响应式画布模糊**：设计尺寸 + `Scale.FIT` + `ResizeObserver`；不要用 CSS 拉伸 canvas。
15. **导入 JSON 不能直接 `v-html` 或 eval**：严格 schema、长度上限、纯文本渲染。
16. **编辑器求解器可能指数爆炸**：所有搜索有预算；超预算返回"无法在预算内验证"，不假装通过。
17. **内容与脚本漂移**：摘要/详情字段重复，用 `content:check` 比对；解/负例/变体都走同一套 `validateArtifact`。
18. **语言切换时序**：先 `await` 补丁再切状态；英文加载失败回落中文。

## 21. 代码风格与协作约定

- 文件命名：`*.logic.ts` 纯逻辑；`*.vue` 组件；`*.scene.ts` Phaser；`*.test.ts` 单测；`*.spec.ts` e2e。
- 导出：模板通过子路径导出（`@mmf/templates/pattern`），避免 barrel 把全部模板拖进共享 chunk。
- 注释：解释"为什么"，不解释"是什么"；每个不显然的约束写一句理由（例如为什么命中区用左上角原点）。
- 提交：一个 PR 只做一件事；内容 PR 与引擎 PR 分开；改预算/改门禁必须写原因。
- 文档：契约改动同步 `docs/02`；关卡改动同步 `docs/03`；门禁改动同步 `docs/04`。
- 没有"临时绕过"：审计红了先修内容，不注释审计；门禁改阈值要单独评审。
