# 自动判定与自动过关（第四轮交互简化）

> 状态：**已实现**。用户诉求：`输入完成后，如果正确直接跳到下一关，如果错误直接直观提示错误原因，整体简化操作流程，只要能得到正确结果即可，尽量减少额外操作`。
> 覆盖：宿主外壳 + 6 个模板 × 20 关 + 16 个工具面板。

---

## 0. 一句话结论

**把"玩家点完成 → 系统判 → 玩家点下一关"这三段，压成"玩家只作答"一段**：

1. 底部「完成」按钮删除，不再有提交动作；
2. 玩家每动一次手，宿主等 500ms 让输入落定，然后看快照里的 `answerComplete`：**填完就自动判**；
3. 答对 → 成功遮罩停 0.9s → **自动进下一关**（最后一关回星图）；答错 → 关卡顶部红色横幅给出**具体原因**（内容里的失败反馈或运行时算出的原因），玩家继续改。

同时把工具面板里"让系统跑一下/显示一下"的按钮全部改成自动执行（倒出整筐、抽两批、运行模拟、预览规律），只保留**答案输入**本身。

## 1. 判定口径：answerComplete 只回答"填完了没有"

契约（`packages/game-kit/src/runtime.ts` + `packages/templates/src/shared/runtime.ts`）：

- `RunSnapshot.answerComplete?: boolean`：玩家答案是否已经填完整；
- `RuntimeAdapter.answerComplete?(state): boolean`：模板自己实现，缺省 false；
- **它不判对错**——对错永远由 `validate` 决定。answerComplete 只决定"什么时候允许自动判题"。

判 false 的典型状态：缺口没补、结论没选、程序还没跑出结果、硬币没付到目标、课次没排满、还没编辑过。

| 模板 / 模式 | 关卡 | answerComplete=true 的条件 |
|---|---|---|
| pattern | k-structure-pattern-path、g13-structure-symmetry | 规律已提交 + 所有缺口已填 |
| rule | k-algorithm-train、g13-algorithm-route | 程序非空，且跑出结果（撞墙/绕圈，或已到终点） |
| construct / distribution | k-modeling-share、g13-modeling-pack | 每一类物品都分完 |
| construct / network | g79-structure-network | 已选边数 ≥ 站点数 − 1 |
| construct / schedule | g79-algorithm-schedule | 每个课次都排进时段 |
| construct / frontier | g1012-algorithm-frontier | 真的改过至少一条边 |
| construct / payment | g46-algorithm-payment | 反例已指出前提 + 台面硬币总额 ≥ 目标（或已放满上限） |
| experiment / tally | k-data-tally、g13-data-weather | 整筐采完 + 统计条已记录 + 结论已选 |
| experiment / duel | g1012-modeling-winrate | 参数凑满 + 采样结果已出 + 结论已选 |
| experiment / sampling | g79-data-sampling | 样本非空 + 结论已选 |
| experiment / inference | g1012-data-inference | 结论已选 |
| simulate / dispatch、queue | g79-modeling-dispatch、g46-modeling-queue | 自动运行结果就绪 |
| argue | 三关 | 依据已选（证据/主张/范围由运行时派生） |

| 位置 | 删掉的额外操作 | 改成 |

## 3. 错误反馈：说清楚错在哪

失败横幅（`failure-banner`）的取文案顺序：

1. 内容 `feedback[failureClass]` 的 `messageKey` + `hintKey`（人话，按失败类写）；
2. 内容没写这一类时，用运行时 `failure.causes[0].messageKey` + `params`（例如"第 3 步撞墙"）；
3. 兜底才是"还差一点" + 关卡 retry 文案。

横幅只在"最近一次判定"存在：玩家一动工具，旧提示立刻消失，不会粘在屏幕上。

## 5. 门禁

- **A11（新增）**：`pnpm audit:levels` 断言每关 autoplay 通关后 `answerComplete === true`——防止某个模板漏实现，让玩家填完也等不到自动判题；
- **e2e**：`level.spec` / `m1.spec` / `budget.spec` 全部改成"作答 → 等 `level:complete` + 离开这一关地址"，不再点「完成」；另加"没作答不会自动判题"的反向用例，以及三条**错误原因直出**用例（统计条对不上 / 站点没连通 / 漏收星星，断言横幅写的是具体原因而不是泛泛的"还差一点"）；
- **UI 冒烟**：`ui-smoke.spec` 断言"自动运行/自动倒出"之后面板真的变了（防"自动执行了但屏幕没反应"）；
- `pnpm verify`（typecheck / lint / 单测 / 内容体检 / 关卡审计 / 打包体检 / build / size）照跑。

**实测（2026-11-07）**：`pnpm verify` 全绿（393 单测；audit A1–A11 全绿，5 条既有 A2 警告未新增）；`pnpm e2e` **78/78** 全绿（约 2.4 分钟）；首屏 69.7 KB gzip、Phaser chunk 220.3 KB gzip、dist 1518.1 KB。

## 6. 已知限制

- rule 关：程序"停在中途"（没到终点、也没撞墙）不算填完，所以不会判题——这是"还没写完"，不是"写错"；画布会显示机器人停在哪。
- 自动判题依赖模板的 answerComplete 实现，谓词写错会让玩家等不到判题；A11 + e2e 预算用例就是为这个兜底。
- 答错后的重试音效、失败运行记录会随每次"改完再判"增加；证据链本来就是"失败→修正"的记录，这里不额外清理。
